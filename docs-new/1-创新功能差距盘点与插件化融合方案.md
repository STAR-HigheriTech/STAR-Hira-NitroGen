# PART14 · NG 创新功能差距盘点 & 插件化融合方案

> **对标对象**：Zen Browser · Arc · Vivaldi · HiraRT（STAR HiraX）
> **被盘点对象**：`1A-STAR_Hira_NG`（`apps/` · `ui/` · `domain/` · `infra/` · `packages/`）
> **口径**：本文件只做**代码实证**调研 —— 每条结论都能落到真实文件或全库 grep。**不涉及门禁 / 登记 / 覆盖率台账**（用户明确要求）。
> **读法**：§1 是"我们已有什么可当底座"，§2 是"别人有什么创新我们还没有"，§3 是"怎么以解耦/插件化方式接进来"，§4 是"现在还缺什么"的执行清单，§5 是建议批次。

---

## §0 一句话结论

NG 的**底盘**（插件系统 / 面板目录 / 空间 / 标签栈 / 分屏 / 主题 / NTP 组件 / 侧栏网页）已经非常完整，其中**分屏（含 2×2 网格、拖拽落点、比例预设、键盘换格）**和**插件化主题系统**已经追平甚至超过对标产品。

真正缺的不是"底层能力"，而是**一组差异化创新功能**（Glance 速览、命令面板、站点定制 Boosts、Easel、命令链宏、手势映射、跨窗口标签同步、Passkey、同步与 AI）以及**若干功能收尾**（网页翻译引擎、自定义搜索引擎、空间级设置、全文检索、历史模型、指纹/代理）。

好消息：**绝大多数缺口都能用 NG 现有的 31 个官方插槽 + 4 类注册机制接进来，不需要新造架构**。第二批深挖（§2.1）又用精确 grep 补出 **16 项**（Peek 小窗、媒体控制中心、整页/选区截图、强制网页深色、按域名分组、复制干净链接、Instant Links、支付/地址填充、容器标签、命名会话、省电、空间导航、分享/QR 等）。

## §1 NG 现有能力基线（后续一切融合的地基）

### 1.1 插件化底座（最核心的可复用资产）

| 机制 | 位置 | 作用 |
| --- | --- | --- |
| 插件 manifest | `apps/app-main/plugins/*.hira-plugin.json`（30 个） | 声明 `id/type/trustLevel/main/render/contributes/capabilities/dependsOn/defaultDisabled/nonDisableable` |
| 四类注册中心 | `infra/infra-plugin/src/` | ProviderRegistry（能力+四级 hook）· ContributionRegistry（声明式数据）· ExtensionPointRegistry（插槽执行，SINGLE/MULTI/REDUCE/EVENT）· service-plugin |
| 官方插槽表 | `infra/infra-plugin/src/official-extension-points.js` | **31 条公共插槽**，新增插槽 = 加一行 |
| 面板目录 | `apps/app-main/src/main/panel-catalog.js` | 面板唯一真源 = 插件 `contributes.panels`，装/禁插件即增删面板 |
| 渲染插槽宿主 | `apps/app-main/src/renderer/shared/plugin-slots.js` + `slots-client.js` | 渲染层 `defineRendererSlots()` 声明宿主槽；第三方回落 `hira-plugin://` |
| 引擎↔UI 联动禁用 | `apps/app-main/src/main/feature-map.js` | 引擎被显式关掉 → 依赖它的 UI 入口**自动隐藏**（fail-open） |
| 隔离宿主 | `plugin-host.js` / `plugin-isolation.js` | 第三方插件跑 `utilityProcess` |
| 市场/安装/打包 | `plugin-market.js` / `plugin-installer.js` / `plugin-archive.js` | 多源市场、zip 安全落盘、sha256 |

## §3 融合架构：怎么做到解耦 / 插件化 / 模块化

### 3.1 四类扩展机制，各管一件事（NG 已是这套，务必沿用）

| 机制 | 管什么 | 什么时候用 |
| --- | --- | --- |
| **ExtensionPointRegistry**（31 官方插槽） | "插槽执行"：单值/多值/归约/事件 | 需要**别人往你的流程里挂东西**时 |
| **ContributionRegistry** | "声明式数据"：面板/主题/格式 | 只需要**贡献一条数据**时（例：`contributes.panels`、`contributes.themes`） |
| **ProviderRegistry** | "能力实现" + before/validate/around/after | 需要**可被替换/拦截的实现**时 |
| **service-plugin + manifest** | 插件生命周期：启停/隔离/市场 | 打包成"可安装/可禁用"的功能时 |

### 3.2 新功能的"标准落点模板"（10 步，任何 §2 条目照此走）

```
1. 纯规则/存储 → domain/domain-<x>（零 electron、零 DOM，可单测）
2. 引擎端口   → infra/infra-<x> 或 infra-window/src/<X>.js（构造注入，不 require electron）
3. 契约+通道   → infra/infra-ipc/src/contracts/<x>.js + packages/shared-types/src/ipc-channels.mjs
4. 主进程装配 → apps/app-main/src/main/ipc/<x>.js（在 ipc-routes.js 聚合）
5. 插件清单   → apps/app-main/plugins/<x>.hira-plugin.json（声明 type / capabilities / contributes）
6. UI 包       → ui/ui-<x>（哑组件，意图回调；不直连 IPC，走 renderer/shared/<x>-client.js）
7. 渲染客户端 → apps/app-main/src/renderer/shared/<x>-client.js
8. 设置项     → main/settings/registry.js（+ appliers/<x>.js 回答"变了做什么"）
9. 引擎↔UI联动 → main/feature-map.js 增一行（引擎禁用 → 入口自动隐藏）
10. 插槽       → 若需被扩展，在 official-extension-points.js 加一行（并注入 zod schema）
```

> 关键红线：**改 UI 入口 ≠ 改核心代码**。面板 = 一个 `contributes.panels`；按钮 = `side-panel.toolbar-action-slot`；菜单项 = `*.context-menu-item`。任何"新增创新功能"若逼你修改 `panel-catalog.js` / `renderer/panels/main.js` 的 switch，说明姿势错了。

## §5 建议落地批次（插件式，每批可独立验收）

| 批次 | 内容 | 交付形态 |
| --- | --- | --- |
| **批次 1**「快速差异化」 | A1 Glance · B4 空间快捷键 · C5 自定义引擎 · D1 命令面板 | 每项 = 1 domain + 1 ui + 1 manifest（命令面板额外加 `command.provider` 插槽） |
| **批次 2**「站点增强」 | C1 Boosts · C2 UserScripts · C3 翻译 · C6 截图 | 新增插槽 `webview.injected-style` / `translate.provider`；UI 走 `webview.context-menu.item` + 新面板 |
| **批次 3**「窗口与手势」 | A5 跨窗口标签同步 · D3 手势映射 · A4 Pin Grid | 新 infra 模块 + `gesture.provider` |
| **批次 4**「组织与检索」 | E1 历史模型 · E2 标签索引 · E3 全文检索 · A2 归档区 · E5 Live Folders | schema 迁移走 `db.schema.migration` |
| **批次 5**「空间与安全」 | B1/B2/B3 空间级设置与导入导出 · I1 Passkey · I2–I4 隐私 | `space.settings-provider` 插槽 |
| **批次 6**「远期平台」 | G1/G2 同步 · H1–H3 AI · D2 命令链 · D4 Easel · B5 共享空间 | `sync.provider` / `ai.provider` 抽象先行 |
| **批次 7**「第二批深挖（低风险高感知）」 | N1 Peek · N16 整页截图 · N5 按域名分组 · N3 强制深色 · N2 干净链接 · N6 Instant Links · N4 媒体控制 | 多数是独立插件/薄模块；截图与媒体控制分别复用 `capturePage` 与 overlay |

**每批的硬性约束（沿用 NG 既有纪律）**：
- 纯规则进 `domain/`，引擎进 `infra/`（构造注入，不 `require('electron')`）；
- 跨进程几何/口径只留**一份** `.mjs`（学 `split-layout.mjs`）；
- UI 入口一律插件化（面板/插槽/菜单项），**不改核心 switch**；
- 新增引擎插件后，在 `feature-map.js` 登记一行，保证"禁用引擎 → 入口自动消失"；
- 死代码与空壳同批清理。
