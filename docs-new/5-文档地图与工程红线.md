## §3 工程红线（所有条目落地必须满足）

> 每条都给出 **NG 已有的范式**（照它做就不会走样）+ **要求**。

### 3.1 性能

- **几何只算一次（主进程），渲染层只画**。范式：`packages/shared-types/src/split-layout.mjs` —— 主进程与渲染层**读同一份**求解器；`resolveDropZone` 的预览块与最终那一格"逐像素一致"。
- **禁止 `getBoundingClientRect` 驱动布局**。范式：`LayoutCoordinator#_pageLayoutParams`（声明式：渲染层只报参数，主进程用 `getContentSize()` 算 bounds）。
- **IPC 合并与去抖**；结构性/内容性变更分开。范式：`infra-ipc/src/ListenerRegistry.js` + `broadcaster`（登记制）；RT 的"结构/内容双队列 + 80ms 去抖"可作参照。
- **动画用同一墙钟曲线**，不用按帧积分的弹簧。范式：`infra-window/src/BoundsTween.js`（`cubic-bezier(0.4,0,0.2,1)` + 180ms + 按边取整消毛刺）。
- **要求**：新功能不得引入"每帧主进程 → 渲染层往返"或重复求解；几何/常量必须**单一事实源**。
- **细则**：P0/P1/P2 全量条目、判据、反例与「少 N 次」台账见 [PART19 性能标准与优化手册](11-%E6%80%A7%E8%83%BD%E6%A0%87%E5%87%86%E4%B8%8E%E4%BC%98%E5%8C%96%E6%89%8B%E5%86%8C.md)。

### 3.2 内存

- **休眠 = 销毁 `WebContentsView`**（不是导航到 `about:blank`）。范式：`infra-window/src/tabLifecycle.js`（注释：每 tab 省 ~20–50MB）+ `tabPreSleep.js` 保存真实 URL/历史。
- **截图/缩略图有 TTL 与上限**。范式：`SnapshotStore.js`（内存 JPEG、TTL 30s / 最多 64 条 / sweep 5s，按需启停）。
- **连接/缓存有 LRU**。要求：新增 DB/连接/大对象缓存必须给**上限 + 淘汰**（PART16 已定 db 连接 LRU ≥3）。
- **有回收阀**。范式：`module-bootstrap.js` 的 `memory.guard`（`app.getAppMetrics()` 驱动）+ `storage.retention`（历史/favicon 定期裁剪）。
- **要求**：任何新面板/新缓存都要回答"**峰值多大、什么时候释放**"。

### 3.3 面板 / 视图及时卸载

- **启动期绝不预热**。范式：`WebContentsManager.js` 注释「启动期绝不预热任何面板 renderer」；`WindowFactory` 惰性创建浮层。
- **关闭即销毁**，不做常驻 keep-alive。要求：面板插件在"收起/切走"时 `destroy()`，下次再按需创建；overlay 同理。
- **要求**：新面板必须在 manifest 与 `panel-views.js` 的 `ensure/has/destroy/reload` 生命周期内工作；**不得**让隐藏面板继续持有渲染进程或定时器。

### 3.3.1 装饰优先走外壳 DOM（能不开视图就不开）

- **先问"这块区域有没有网页盖着"**：网页是原生 `WebContentsView`、chrome（窗口本体）在所有子视图**之下** —— 所以**凡是不被网页覆盖的地方，chrome 都拿得回来**。装饰画在那里：**零渲染进程、零图层、零 IPC 家族**，且外壳 DOM **永远抢不走原生视图的点击**。
  范式：`renderer/shared/split-surface.js`（分屏分隔条 + 活动格框）、`web-sidebar-surface.js`（侧栏聚焦框 + 调宽把手）、`glance-surface.js`（速览整叠卡片的外环阴影）—— 三者的文件头都写着同一段推理；**三处的聚焦框同色同宽**（线宽真源 = `SPLIT_METRICS.paneGap`，颜色 = `--hira-split-focus-ring`）。
  ⚠ 颜色**别**用 `--hira-focus-ring`：那是 **box-shadow 列表**（`0 0 0 2px rgba(...)`），当颜色用会让声明「计算值非法」→ 落回 `initial`（背景透明 / 边框 currentColor）且**不报错**。侧栏调宽线曾因此"怎么调都不显示"。
- **拿不回来时：画进那一页里（`insertCSS`），别开浮层**。判据是**几何**而不是"想不想"：速览的卡间投影 + 蓝聚焦框要环绕**前台卡**，可 front 卡（0.85×0.93）的**左右两条边正坐在 back 卡（0.95×0.975）身上** —— 那一片像素归 back 卡这张原生视图所有，外壳 DOM 到不了；而盖在卡片之上的浮层视图又会吃掉点击（见下一条反例）。做法：注入 **back 卡那一页**（`infra/infra-window/glance-deck-chrome.js`），框带**落在 front 矩形之外、back 视口之内** ⇒ 它在网页内容之上、又不会被任何圆角裁切；外轮廓半径 = `front 圆角 + 框宽`，与 front 的裁切同心，内缘 1px 藏进 front 卡底下（无半像素缝）。圆角值不写死：与主浏览视图同源（`LayoutCoordinator._pageRadius()` ← 主题 `style.cornerRadius`，全屏贴边归零）。代价要明说：它属于那一页的渲染结果，**页面截图与标签预览缩略图会带上它**（用 `@media screen` 把打印排除）。
- **反例（实测踩过）**：为速览阴影开了一个**铺满整片内容区、盖在卡片之上**的浮层视图，并指望 `setIgnoreMouseEvents` 穿透 —— 结果把「点背景卡 → 提升前台」与网页点击**全吃掉了**。真相：`View` / `WebContentsView` **没有可用的** `setIgnoreMouseEvents`，**视图只要可见就参与命中**（见 `renderer/hoverurl-overlay/main.js` 的注释 —— `setFloatPointerAvoid` 那套 30fps 指针避让就是被这条逼出来的）。
- **确实要被盖住时的唯一退路**：**少占面积**（如悬停 URL 提示条只留 2px 余量），而不是指望穿透。

### 3.4 闪烁（重中之重）

- **同帧落位**：结构性变化时，新视图与旧视图在**同一帧**完成切换。范式：Glance 的 front/back 布局（PART13-C1）——"同帧落位避免闪动"。
- **预览 = 真实**：预览/占位与实际结果**逐像素一致**。范式：`dropZonePaneRect` 与 `solveSplitPanes` 同式。
- **复用 DOM，不重建**：列表项走"创建一次 + `sync(...)` 更新"。范式：`ui/ui-tabbar/src/components/Tab.js`（`LIVE_FLAGS` + `sync`）、`TabStack.js`（`sync('collapsed', …)`）。
- **原生视图的四类写入都要去重（值没变就别写）** —— 它们不是普通属性赋值，代价是**那一层视图的合成表面被重建**：
  1. `setBounds` → `_setBoundsIfChanged`（`_lastBounds` WeakMap，按 view 隔离）；
  2. `setBorderRadius` → `_setRadiusIfChanged`（`_lastRadius` WeakMap）—— 它要**重做圆角遮罩**，而这个调用原先散在 7 处、每趟布局都无脑写；
  3. `setVisible` → 读**原生真实状态** `View#getVisible()` 再决定写不写（`_setVisibleTabs` 里的 `_isViewShown/_isViewHidden`）。⚠ 刻意**不自己记一份"谁亮着"的账本**：全仓有六七处直接写 `setVisible`，账本迟早失真，而失真的表现是**"该亮的没亮"**（比多写一次严重得多）。浮层的那套 `Layer#setVisible` 本来就自带变化检测，所以只有**裸的标签视图**需要这一层。
  4. `addChildView` → **这是"重排"**（Electron 文档：*if the same View is added to a parent which already contains it, it will be reordered such that it becomes the topmost view*，内部=摘下来再挂上去）。所以"抬到顶层"（`_raiseTabView`）必须先读 `parent.children` 确认它**不在顶层**再写 —— 否则每趟布局都会重建一次前台的合成表面（速览路径每趟布局都走到这一步）。
- **结构性切换的原生写入必须收在同一个 tick 里**：新出现的视图"切可见"与"落 bounds"要在同一次同步执行里做完（同 tick 内的多次原生写入在**同一帧**生效，所以顺序无所谓；但中间一旦 `await` / 跨帧，就会"先以旧尺寸露一下"再跳过去 = 闪）。
- **启动期判定稳定**：`feature-map.js` 的"fail-open + 只看显式关闭"，避免界面"先隐藏再冒出"。
- **要求**：新功能必须说明"**首帧怎么落**""**切换时会不会重建 DOM**"。
- **细则**：[PART19 §6 不闪烁](11-%E6%80%A7%E8%83%BD%E6%A0%87%E5%87%86%E4%B8%8E%E4%BC%98%E5%8C%96%E6%89%8B%E5%86%8C.md) 的 9 条硬规则与验收方法。

### 3.5 完全解耦 / 插件化 / 模块化

- **四层依赖单向**：`domain`（纯规则，**不 require electron**）→ `infra`（引擎，构造注入）→ `ui`（哑组件，**不 import apps/pages**）→ `apps`（装配）。
- **能力经插件与插槽暴露**：功能 = 插件 manifest（`contributes`）+ 官方插槽（`official-extension-points.js`，31 条）+ ProviderRegistry（四级 hook）；**不改核心 switch**。
- **引擎↔UI 联动**：`feature-map.js` 增一行 —— 引擎被禁用 → 依赖它的入口自动隐藏。
- **端口注入而非直接依赖**：如 `domain-profile` 不 `require domain-space`，用 `spacePort` 鸭子端口。
- **单一事实源**：几何（`split-layout.mjs`）、键位（`layout.mjs`）、层级（`shared-ui-tokens/layers.css` + `--hira-z-*`）、面板目录（`panel-catalog.js`）。
- **要求**：新功能落地后，**核心文件不应新增分支**（`panel-catalog` / `renderer/panels` / `LayerManager` 不应被改）。

### 3.6 不臃肿（能加不建）

- 能复用现有面板/插件/取色/列表/音频/订阅源等基建的，**一律加法**（见 PART17 §2）。
- **同一能力只留一条通道**：Boosts / 强制深色 / UserScripts 共用注入通道（§2 J10）。
- **合并重复项**：截图 C6 与 N16 合并；每站主题并入注入通道。
- **砍掉低收益**：见 PART17 §5/§6。

4. **首帧怎么落**？切换会不会**重建 DOM**（闪烁）？
5. **面板/视图何时卸载**？有哪些**常驻定时器/监听/渲染进程**？
6. **内存峰值**多少？缓存**上限与淘汰**是什么？
7. **启动期**会不会 eager 预热？会不会阻塞首屏？
8. 是否引入**主进程↔渲染层每帧往返**？
9. **依赖方向**对不对？（domain 不碰 electron、ui 不碰 apps）
10. 是否**新增核心文件分支**？（应当靠 manifest/插槽完成）
11. **引擎禁用**时入口是否自动隐藏（`feature-map`）？
12. **profile 维度**：数据带 profile 作用域 / 设置项归属明确（PART16 §3）？
13. 与已有能力是否**重复**？重复的是否已合并？
14. **接入面**是否≥1（设置项 / 触发〔菜单·地址栏命令·快捷键·拖拽〕/ 面板 / 浮层 / **overlay** / 内嵌）？
    **只做能力层、不给任何一个入口 = 未完成**（逐项矩阵见 PART17 §11.4）。

## §5 反模式（禁止）

| 反模式 | 为什么 |
| --- | --- |
| 新增浮层绕过 `LayerManager` / 裸写 z-index | 破坏层级单一事实源（`--hira-z-*` 已有门禁） |
| `ui/*` import `apps/*` 或 `pages/*` | 反向依赖（CONTRACT-11） |
| `domain/*` require `electron` / DOM | 破坏纯层可单测 |
| 几何/键位/层级**各写一份** | 迟早漂移（"预览与真实差几像素"） |
| 面板 keep-alive 常驻、启动期预热 | 内存与启动时间双输 |
| 为每个站点定制各做一套（Boosts/深色/脚本） | 臃肿，应三合一 |
| profile 数据不带作用域 / 设置项无归属 | 多用户串数据 |
