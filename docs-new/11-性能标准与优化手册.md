# PART19 · 性能标准与优化手册（跟手 · 流畅 · 不阻塞 · 不闪烁 · 不抖动 · 内存 · 波及）

> **定位**：[PART18 §3](5-文档地图与工程红线.md) 是"红线一句话"，本文是它的**可执行全集**：
> 分级条目（P0/P1/P2/P3）+ 判据 + 反例 + 本仓正例 + 验收方式 + 量化台账。
>
> **口径**：所有正例都取自本仓真实代码（附文件路径），不是通用鸡汤。
> 与 PART18 冲突时以本文的**分级条目**为准（PART18 是摘要，本文是细则）。
>
> **一句话**：性能不是"最后再优化"，是**每一次提交都必须通过的门禁**。

## §0 三条总纲 + 一条纪律

| 编号 | 总纲 | 落地含义 |
| --- | --- | --- |
| G1 | **单帧预算制** | 主进程一次同步执行 ≤ **8ms**（留一半给 Chromium 合成/GC），渲染层一帧 ≤ **16.7ms**。任何可能超出的块：拆、延后、合批，三选一。 |
| G2 | **谁持有谁付费** | 每个常驻对象（视图 / 监听 / 定时器 / 缓存 / 连接 / 大对象）必须能当场回答三问：**峰值多大？谁释放？什么时候释放？** 答不出 = 不许合入。 |
| G3 | **一次只做一件事** | 用户动作那一拍**只做"看得见的变化"**；落盘、休眠、清理、重放、统计、上报一律推到下一拍（`setTimeout 0`）或合批窗口。 |
| G4 | **无净账不改**（纪律） | 任何性能改动必须在提交说明里写出：`净减少 N 次 X / 净新增 M 次 Y`。只写"优化了"不算。**净新增常驻开销的改动默认拒绝**。 |

> G4 是硬纪律：历史上有一版"静音媒体也回收"因为增加了常驻判定开销被判定为负收益并回滚 —— 这类判断不靠感觉，靠净账。

## §1 术语、阈值与度量口径

先把词定死，否则"卡"这个字会掩盖七种完全不同的问题。

| 术语 | 定义 | 阈值（P0 门禁） | 常见误诊 |
| --- | --- | --- | --- |
| **跟手性** | 输入（按下/移动/点击）→ **第一帧可见反馈**的延迟 | 目标 ≤ 16ms；操作可交互 ≤ 100ms | 误当成"渲染慢"，其实是主进程在同步写盘 |
| **流畅性** | 连续帧的间隔稳定性 | 帧间隔 **P95 ≤ 20ms**；动画期间最长帧 ≤ 50ms | 只看平均帧率会掩盖单次 200ms 长帧 |
| **阻塞** | 主进程/渲染主线程的**同步执行块** | 单块 ≤ 8ms；>16ms 一票否决 | "CPU 不高但就是卡" = 单次长同步块，不是占用率 |
| **闪烁** | 同一元素在 ≤2 帧内出现两次不同几何/内容/可见性 | **0 次** | 误以为是动画，其实是"先旧尺寸露一下再跳" |
| **抖动** | 稳态下（非动画驱动）同元素相邻帧几何变化 | **0 次** | 误以为是渲染问题，其实是布局读写交替（layout thrash） |
| **波及** | 一次用户动作导致**与动作无关**的视图/窗口/空间重算、重渲染、IPC | 影响集合必须**可枚举**且最小 | "点一个按钮，另一个面板白屏一下" = 广播范围过大 |
| **常驻内存** | 空闲 N 分钟后的基线 RSS + 进程数 | 空闲 5 分钟漂移 ≤ 5% | 只看任务管理器总数，看不见 renderer 进程数 |
| **动作增量** | 动作前 → 动作峰值的内存差 | 切标签 ≤ 30MB；切空间 ≤ 60MB（含新空间首屏） | 把 Chromium 的缓存增长算成泄漏 |

**"少 N 次"记法**：把优化写成 `O(N) 次/动作 → O(1) 或 0 次/动作`。
本文 §10 是台账；没进台账的优化，视为未验证。

**测量位置必须写清**：主进程阻塞看 Node 侧同步块耗时；跟手性看输入事件 → 首个 `requestAnimationFrame` 后的可见变化；内存看 `app.getAppMetrics()`（主进程）而不是任务管理器。

## §2 分层预算与责任矩阵

> 分层本身就是性能设计：**越靠下的层越不该知道"界面"**，越靠上的层越不该做"重活"。

| 层 | 允许 | 禁止 | 预算 |
| --- | --- | --- | --- |
| `domain/*` | 纯规则、纯换算、纯校验 | `require('electron')`、DOM、同步 IO、定时器 | 单函数 ≤ 1ms（纯计算） |
| `infra/*` | 引擎能力：视图生命周期、布局、存储、IPC 总线 | 业务分支、UI 文案、直接依赖 `apps` | 单次原生写操作成组 ≤ 8ms |
| `ui/*` | 哑组件：渲染 + `sync(...)` | 订阅 IPC、发请求、读数据库、持有全局状态 | 单次 `sync` ≤ 4ms |
| `apps/*/main` | 装配、编排、权限、策略 | 逐帧计算、同步大 JSON、在热路径写盘 | 单次编排 ≤ 8ms |
| `apps/*/renderer` | 编排 + 视图装配、rAF 合批 | 大对象跨 IPC、同步 XHR、布局读写交替 | 单帧 ≤ 16.7ms |
| `shared-types` | 常量/几何/协议的**唯一事实源** | 任何运行时副作用 | 零 |

**三条跨层铁律**

1. **几何只算一次**：主进程算，渲染层只画。范式：`packages/shared-types/src/split-layout.mjs`（`solveSplitPanes` / `dropZonePaneRect` 同一份算术）。
2. **IPC 不搬大数据**：单条 payload ≤ 64KB；超过就分页、按需拉、或只发"变更描述"。
3. **渲染层不做持久化**：落盘一律回主进程，且不在用户动作那一拍。

## §3 P0 必须项（红线，违反即回滚）

> 22 条。每条都能在代码里指出"违反了会怎样"。

### 3.1 跟手 / 阻塞

**PERF-P0-01｜用户动作那一拍不落盘**〔跟手·阻塞〕
- 判据：点击/按键处理函数内不得出现 `fs.write*Sync`、SQLite 同步写、`JSON.stringify(大数据)`、`capturePage` 等待。
- 反例：切 space 时同步把整空间会话（每标签含 base64 导航历史）序列化写盘。
- 正例：`main.js#switchSpaceOnRuntime` 把 `saveSpaceSession` 放到 `setTimeout(0)`，且端口钉死旧空间。
- 验收：在动作处理函数里打断点/打日志，同步段耗时 < 8ms。

**PERF-P0-02｜用户动作那一拍不做批量销毁**〔跟手·内存〕
- 判据：一次动作最多销毁**一个**视图（被替换的那个）；N 个视图的回收必须延后/分片。
- 正例：`TabManager#setCurrentSpace` 把旧空间 `_sleepSpaceTabs` 延后一拍。
- 补丁：延后任务必须在执行时**复核当前空间**，防止"下一拍又切回来"把眼前视图销毁（见 `TabManager.js` 定时器内 `_context.getCurrent` 比对）。

**PERF-P0-03｜热路径没有同步 IO / 无界计算**〔阻塞〕
- 判据：`tab:changed`、`bounds`、`scroll`、`pointermove` 的处理器里不允许 IO、正则回溯、全量排序。
- 反例：每次标签事件重建整棵标签树并序列化。

**PERF-P0-04｜每个事件都必须合批或有明确上界**〔流畅〕
- 判据：高频事件（标签增删改、页面加载状态、尺寸变化、主题变化）必须有 ≤ 1 帧的合批窗口。
- 正例：`infra-window/src/TabChangeEmitter.js`（`EMIT_COALESCE_MS = 16`）、`LayoutCoordinator` 的布局重试定时器。

**PERF-P0-05｜渲染层不得每帧与主进程往返**〔阻塞·跟手〕
- 判据：任何"每帧一次 `ipcRenderer.invoke`"的设计直接否决。
- 正例：拖拽/分屏预览由渲染层本地求解（共享 `split-layout.mjs`），只在**落定**时回报一次。

### 3.2 闪烁 / 抖动

**PERF-P0-06｜结构性切换必须同帧落位**〔闪烁〕
- 判据：新视图"切可见"与"落 bounds"必须在**同一个同步 tick** 内完成；中间不得 `await`。
- 正例：Glance front/back 布局；`LayoutCoordinator` 内结构性写入成组执行。
- 反例：先 `setVisible(true)`，等一个 IPC 回来再 `setBounds` → 先以旧尺寸露一帧。

**PERF-P0-07｜原生视图写入必须去重（值没变不写）**〔闪烁·流畅〕
- 四类写入的代价是**那一层合成表面重建**，不是普通赋值：
  1. `setBounds` → `_setBoundsIfChanged`（`_lastBounds` WeakMap）；
  2. `setBorderRadius` → `_setRadiusIfChanged`（`_lastRadius` WeakMap）；
  3. `setVisible` → 读原生 `View#getVisible()` 再决定（**刻意不自己记账本**，账本失真会导致"该亮的没亮"）；
  4. `addChildView` → 先读 `parent.children` 确认不在顶层（同一父级重复添加 = **重排** = 重建合成表面）。
- 正例：`infra-window/src/LayoutCoordinator.js`；`_raiseTabView` 的顶层判定。

**PERF-P0-08｜列表/面板更新复用 DOM，不重建**〔闪烁·内存〕
- 判据：列表项"创建一次 + `sync(...)` 更新"，禁止 `innerHTML = ''` 后重建。
- 正例：`ui/ui-tabbar/src/components/Tab.js`（`LIVE_FLAGS` + `sync`）、`TabStack.js`（`sync('collapsed', …)`）。

**PERF-P0-09｜首帧判定必须稳定**〔闪烁〕
- 判据：功能开关/能力探测不得"先渲染出入口再隐藏"。
- 正例：`feature-map.js` 的 fail-open + 只看显式关闭。

**PERF-P0-10｜布局读写必须分离**〔抖动〕
- 判据：同一帧内禁止"读 `getBoundingClientRect` → 写样式 → 再读"的交替；所有读先做，所有写后做。
- 反例：循环里逐个 `el.style.width = ...` 后又 `el.offsetWidth`。

### 3.3 内存 / 生命周期

**PERF-P0-11｜休眠 = 销毁 `WebContentsView`**〔内存〕
- 判据：禁止用 `about:blank` 或 `loadURL('')` 假装休眠。
- 正例：`infra-window/src/tabLifecycle.js`（每标签省 ~20–50MB）+ `tabPreSleep.js` 保存真实 URL/历史。

**PERF-P0-12｜任何缓存必须有上限 + 淘汰**〔内存〕
- 判据：新增 Map/数组缓存必须写 `maxEntries` 与 `ttl`，且提供 `clear()`。
- 正例：`SnapshotStore`（TTL 30s / 最多 64 条 / sweep 5s，按需启停）；`logHub`（容量 5000 环形）。

**PERF-P0-13｜关闭即销毁，不 keep-alive**〔内存〕
- 判据：面板/浮层收起时必须释放渲染进程；禁止"藏起来以后快"。
- 正例：`WebContentsManager` 的 `ensure/has/destroy/reload` 生命周期；启动期**绝不预热**面板 renderer。
- 例外（唯一）：`0×0 + visible` 的预取视图，且**必须在收起态恢复节流**（见 P0-14）。

**PERF-P0-14｜隐藏视图必须节流**〔流畅·内存〕
- 判据：同一窗口内只要有**任一** `displayed` webContents 关了 `backgroundThrottling`，**整窗所有视图**每帧都被驱动。
- 正例：`infra-window/src/webPreferences.js` 显式 `backgroundThrottling: true`；`LayoutCoordinator#_syncFloatThrottle` 在浮层收起/销毁时恢复节流（只记跳变，稳态零调用）。
- 反例：浮层开一次后永远不关节流 → 窗口空闲时仍在出帧。

**PERF-P0-15｜定时器必须可停**〔内存·波及〕
- 判据：轮询/扫表类定时器在没有订阅者时必须停表；停止后不留句柄。
- 正例：`createCursorEdgeMonitor`（30fps，无订阅者即停）、`SnapshotStore` 的 sweep 按需启停。

**PERF-P0-16｜订阅必须可回收**〔内存〕
- 判据：任何 `on/once/addEventListener/ipcRenderer.on` 必须返回或登记 disposer；模块销毁时全部执行。
- 正例：`createSpaceController` 的 `disposers` 栈；`ListenerRegistry` 的登记制。

### 3.4 作用域 / 波及

**PERF-P0-17｜异步任务必须钉死作用域**〔波及·正确性〕
- 判据：凡是"延后/合批/异步"的任务，其读取的 profile / space / window / tab 必须在**创建任务时**快照，不得在执行时read"当前环境"。
- 正例：`createSessionTabPort(tabManager, { space })` 的 `pinned`；`saveSpaceSession(rt, dir, { space })`；`TabManager#getActiveTabIdForSpace`。
- 反例（已修）：端口读环境当前空间 → 切完之后写进别的空间目录，重启后旧空间冒出别人的标签。

**PERF-P0-18｜状态操作必须幂等**〔波及〕
- 判据：`setCurrentSpace` / `setProfile` / `showPanel` 重复调用同一目标时，不得产生任何销毁/重建。
- 正例：`setCurrentSpace` 的 `sameSpace` 守卫（否则本空间 N 个渲染进程被白销毁一遍）。

**PERF-P0-19｜广播必须分级且默认最小**〔波及〕
- 三级：`targeted`（单 webContents/单窗口）→ `window`（同窗所有视图）→ `broadcast`（全部窗口）。
- 判据：新增事件先问"最远需要到哪一级"，默认 targeted；`scope:'all'` 需要理由。
- 正例：`ipc/space.js#setUsing` 只向目标窗口发 `space:window-changed`；空间级设置重放只发 `scope:'one'`。

**PERF-P0-20｜值没变就不广播**〔波及〕
- 判据：设置重放、主题应用、状态同步前先比较；对象值用稳定序列化比较。
- 正例：`main.js#replaySpaceScopedSettings` 的 `lastReplayedSpaceSettings` 签名比较（只记录"发出去过的值"，最坏多发一次，绝不漏发）。

### 3.5 启动与资源

**PERF-P0-21｜启动期禁止 eager 预热与同步全量读盘**〔跟手·内存〕
- 判据：首屏可交互前不得创建面板 renderer、不得全量扫描数据库、不得同步解析大配置。
- 正例：`WebContentsManager` 的"启动期绝不预热任何面板 renderer"；`WindowFactory` 惰性创建浮层；`SnapshotStore` 启动时不扫。

**PERF-P0-22｜新增常驻开销必须写释放点**〔内存〕
- 判据：新增一个常驻监听/定时器/缓存/进程，必须在同一提交里写清释放路径与触发条件；否则一票否决。
- 这条是 G2 的执法条款。

## §4 P1 基本项（每次改动的最低要求）

> 24 条。达不到不算"性能缺陷"，但**评审必查**。

### 4.1 事件与数据

| 编号 | 条目 | 判据 / 正例 |
| --- | --- | --- |
| PERF-P1-01 | 结构变更与内容变更分开通道 | 结构（增删/换序）低频不走内容队列；内容（标题/图标/加载）高频合批 |
| PERF-P1-02 | 变更只发差量 | 标签列表投影只发变化的字段；禁止每次发整份记录含历史 |
| PERF-P1-03 | 落地投影与内存投影分离 | `list()`（轻）与 `listForPersist()`（重，含导航历史）分开，热路径只调前者 |
| PERF-P1-04 | 大数据按需拉 | 历史/书签/密码列表分页；面板打开时只拉首屏 |
| PERF-P1-05 | 快照/缩略图先占位后替换 | 占位尺寸与真实一致（防 CLS），拿到真实图再换 `src` |
| PERF-P1-06 | 预取按意图触发 | 指针进入触发器（`pointerenter`）才预热浮层，不按时间盲预取 |
| PERF-P1-07 | 图片/字体有尺寸与 `loading` 策略 | `width/height` 或 `aspect-ratio`；非首屏 `loading="lazy"` |

### 4.2 渲染

| 编号 | 条目 | 判据 / 正例 |
| --- | --- | --- |
| PERF-P1-08 | 动画只动 `transform` / `opacity` | 不动 `width/height/top/left`（触发布局） |

| PERF-P1-13 | 滚动容器单一 | 避免嵌套滚动导致的滚动锚定失效 |
| PERF-P1-14 | 文本容器宽度稳定 | 预留宽度/`min-width`，避免加载中文字换行导致高度跳变 |

### 4.4 资源与错误路径

| 编号 | 条目 | 判据 / 正例 |
| --- | --- | --- |
| PERF-P1-20 | 失败路径也必须释放 | `try/finally` 清理 timer、inflight 标记、临时视图 |

## §5 P2 高级项（热路径专项，需净账）

> 18 条。只在**切换 / 输入 / 播放 / 滚动**这几条热路径启用，且必须写净账（G4）。

**PERF-P2-01｜"动作帧只上屏，重活延后一拍"**〔跟手〕
范式：`switchSpaceOnRuntime` 的会话保存 + `setCurrentSpace` 的旧空间休眠，全部 `setTimeout(0)`。

**PERF-P2-02｜延后任务必须带"失效复核"**〔正确性〕
范式：休眠定时器内比对 `_context.getCurrent()` 与目标空间，不一致就放弃。

**PERF-P2-03｜同一动作只发一次全量投影**〔波及〕
范式：`switchTo` 已 `_emitNow`，`setCurrentSpace` 尾部不再补 `_scheduleEmitChanged`。

**PERF-P2-04｜会话落盘：脏标记 + 固定间隔批量**〔阻塞〕
范式：`domain-session/src/sessionPersistence.ts`（2s 合批异步 flush，对齐 RT `FLUSH_INTERVAL_MS`），高频 `tab:changed` 不再逐次写盘。

**PERF-P2-05｜设置重放做值去重**〔波及〕
范式：`replaySpaceScopedSettings`（两空间主题/指纹相同则不跑 applier）。

**PERF-P2-06｜浮层收起即节流，展开前预热**〔流畅〕
范式：`LayoutCoordinator#_syncFloatThrottle` + 触发器 `pointerenter` 的意图预热。

**PERF-P2-07｜轮询停表**〔内存〕
范式：`cursor-edge-monitor` 无订阅者即停。

**PERF-P2-08｜快照双淘汰**〔内存〕
范式：`SnapshotStore` TTL 30s / 64 条 / 5s sweep，按需启停。

**PERF-P2-09｜结构性原生写入收在同一 tick**〔闪烁〕
范式：同 §3 P0-06。

**PERF-P2-10｜几何单一事实源**〔闪烁〕
范式：`split-layout.mjs` 同时供主进程与渲染层。

**PERF-P2-11｜渲染层只报参数，主进程算 bounds**〔阻塞〕
范式：`LayoutCoordinator#_pageLayoutParams` + `getContentSize()`。

**PERF-P2-12｜窗口 resize 合批，重活只在结束做**〔流畅〕
判据：`resize` 期间只写 bounds；重排/重算放到 120–200ms 静默后。

**PERF-P2-13｜输入事件不触发同步布局**〔跟手〕
判据：`pointermove` 里只更新变量 + 标记脏，rAF 内统一写。

**PERF-P2-14｜媒体播放的前台优先**〔流畅〕
判据：前台播放的视图不参与任何周期性重排/重绘；装饰层不盖在视频上。

**PERF-P2-15｜IPC 回包最小化**〔阻塞〕
判据：返回 `{ok:true}` 而不是整份对象；调用方需要全量时再拉。

**PERF-P2-16｜失败重试有退避与上限**〔波及〕
判据：布局重试/加载重试必须指数退避 + 上限，禁止 0ms 死循环重试。

**PERF-P2-17｜退出/切换时取消在途任务**〔内存〕
判据：`AbortController` 或 generation 计数，旧任务发现代际变化即丢弃结果。

**PERF-P2-18｜构建产物体积纳入性能**〔启动〕
判据：主进程入口单文件化（`bundle-shared-runtime`）、避免重复依赖；体积变化写进提交说明。

## §6 专项：不闪烁（9 条硬规则）

1. **同帧落位**：可见性与几何同一 tick（P0-06）。
2. **预览 = 真实**：占位/预览与最终结果**逐像素一致**（`dropZonePaneRect` ≡ `solveSplitPanes`）。
3. **先测量后切换**：新内容先离屏布局/取尺寸，再一次性替换；不允许"空 → 半成品 → 成品"。
4. **首帧判定稳定**：功能可用性在首屏渲染前已确定（`feature-map` fail-open）。
5. **主题不重建**：只换 CSS 变量与令牌，不重挂 DOM（P1-15）。
6. **图片预留尺寸**：`width/height` / `aspect-ratio`，禁止图片加载完成后撑开布局。
7. **占位与真实布局同构**：骨架屏的行高/列宽 = 真实卡片，避免 CLS。
8. **视图销毁与替代创建同拍**：先建后销（或同一 tick 内完成），不出现"两者都不在"的空窗。
9. **避免 0 尺寸露一帧**：预取视图在显示前必须已经落好 bounds（预取阶段就写入，见 `WebContentsManager` 的 0×0 策略）。

**验收**：对同一动作录 120fps 屏幕捕获，逐帧检查目标区域——不允许出现"旧内容一帧 + 新内容一帧"或"空白一帧"。

---

## §7 专项：不抖动（8 条硬规则）

1. **布局读写分离**：一帧内"读—读—读，写—写—写"（P0-10）。
2. **原生 bounds 取整**：按边 `Math.round`，避免半像素边缘抖动。
3. **动画统一墙钟曲线**：不按帧累加（帧率波动会导致距离不一致）。
4. **滚动锚定**：动态插入内容时保持可视锚点（`overflow-anchor` 或手动补偿）。
5. **宽度稳定**：工具栏/地址栏的按钮按需占位，不因文字长度变化推挤。
6. **rAF 合批写样式**：一次 rAF 内合并所有写入，避免多次样式重算。
7. **resize 期间不重排**：只更新必要几何，静默后再做重活（P2-12）。
8. **字体加载不改变度量**：`font-display: swap` + 预留行高，避免文字回流。

**验收**：静止界面录 3 秒，任意相邻帧同一元素边界差 = 0。

## §8 专项：内存与进程

### 8.1 生命周期表（每个视图都必须能填）

| 阶段 | 允许持有 | 必须释放 |
| --- | --- | --- |
| 创建 | webContents、监听、窗口引用 | — |
| 前台激活 | 渲染进程、合成层、媒体解码器 | — |
| 后台（同空间不可见） | webContents（保留会话） | 定时器、动画、媒体（按策略） |
| 休眠（跨空间） | 仅快照：URL + 历史 + 一帧 JPEG | **WebContentsView 本体**（省 20–50MB/标签） |
| 销毁 | 无 | 监听、timer、快照引用、闭包大对象 |

### 8.2 预算（默认值，超出需说明）

| 对象 | 预算 | 淘汰 |
| --- | --- | --- |
| 标签休眠快照 | ≤ 64 条 / 单条 ≤ 200KB | TTL 30s + 条数上限 |
| 标签页截图 | 同上 | 同上 |
| DB 连接 | ≤ 3（profile LRU） | LRU |
| 日志缓冲 | 5000 条环形 | 覆盖写 |
| 面板/浮层 renderer | 关闭即 0 | 销毁 |
| 空闲基线漂移 | ≤ 5% / 5 分钟 | 超了就查泄漏 |

### 8.3 泄漏点黑名单（逐条排查）

- 监听未解绑（`webContents.on` / `ipcMain.on` / `app.on`）
- `setInterval` 无人 `clear`
- `WebContentsView` 从 children 移除但未 `webContents.close()`
- 闭包持有整份标签列表/整段 base64
- `dataURL` / `Blob` 存进长期 Map
- `capturePage` 的 Buffer 未进入有上限的 store
- `Promise` 链持有 `win` 引用导致窗口无法回收

**排查动作**：空闲 5 分钟 → 切 10 次空间回来 → 再空闲 5 分钟，比较 renderer 进程数与 RSS；差值应回到基线 ±5%。

## §9 专项：波及控制（blast radius）

**定义**：用户做 A，系统重算了 B。B 越远，越不可接受。

| 级别 | 通道 | 使用条件 |
| --- | --- | --- |
| L0 targeted | 单 `webContents.send` / 单窗口 | 默认；能 L0 不用 L1 |
| L1 window | 同窗所有视图 | 只用于"确属同窗共享状态"（如窗口级布局） |
| L2 broadcast | 全窗口 | 仅用于全局事实（主题包切换、语言、账号） |

**四条纪律**

1. **作用域快照**：异步任务带 profile/space/window 快照（P0-17）。
2. **值比较**：同值不广播（P0-20）。
3. **代际计数**：切走即弃旧任务结果（P2-17）。
4. **影响集合可枚举**：提交说明必须写"这个动作会影响哪些视图"，写不出 = 设计没想清。

**范式**：`ipc/space.js#setUsing` 只发目标窗口；`replaySpaceScopedSettings` 只发 `scope:'one'`；`space-controller` 用 `inflight` 合并并发刷新。

## §11 反模式黑名单（禁止出现）

| 反模式 | 后果 |
| --- | --- |
| 点击处理里同步写文件/写库 | 跟手性直接崩（一帧几十 ms） |
| 每次事件都全量 `list()` + 序列化 | 事件风暴 → 主进程堵死 |
| 隐藏面板保持 `backgroundThrottling: false` | 整窗持续出帧，风扇转 |
| `setVisible(true)` 与 `setBounds` 分两个 tick | 先旧尺寸露一帧 = 闪 |
| 同一父级重复 `addChildView` | 重排 + 合成表面重建 |
| 自己维护"谁可见"的账本 | 账本失真 → "该亮的没亮" |
| 列表 `innerHTML = ''` 重建 | 闪烁 + 丢失滚动位置 + GC 压力 |
| 每帧 `ipcRenderer.invoke` | 主进程排队，输入延迟累积 |
| `setInterval` 无人清理 | 内存 + CPU 双泄漏 |
| 全窗口广播局部状态 | 波及所有视图/窗口 |
| 用 `about:blank` 当休眠 | 内存不降反升（视图还在） |
| 异步任务读"当前空间" | 跨空间串档（最隐蔽的一类） |
| 缓存无上限 | 长时间使用后 OOM |
| 启动期预热所有面板 | 首屏慢 + 常驻内存高 |
| 用 0ms 重试循环修复布局 | CPU 打满，且掩盖真正原因 |
| 在 `pointermove` 里读布局 | layout thrash，输入掉帧 |
| 动画改 `width/top` | 每帧布局 + 重绘 |
| 子像素 bounds | 边缘抖动/毛刺 |
| 日志里 `JSON.stringify` 整个事件对象 | 高频路径开销爆炸 |
| 预览与最终几何各写一份 | 差几像素 = 永远修不完的"跳一下" |

## §13 手工验证剧本（不写自动化脚本）

> 原则：性能验证靠**真实操作 + 录屏 + 进程指标**，不靠跑一堆测试脚本。

### 13.1 5 分钟冒烟（每次改动）

1. 冷启动到可交互：秒表计时，记录首屏时间；任务管理器记录进程数。
2. 连开 10 个标签（含视频页），来回切 20 次：肉眼观察是否有"空白一帧/旧尺寸一帧"。
3. 打开/收起两个浮层各 10 次：收起后等待 10 秒，用 DevTools Performance 录 2 秒，确认**无持续出帧**。
4. 切 space A→B→A 各 5 次：观察是否闪、是否卡；切回后标签是否原位。
5. 空闲 2 分钟：观察内存是否持续上涨（`app.getAppMetrics()`）。

### 13.2 15 分钟深测（性能相关改动）

1. **长任务**：渲染层 Console 跑
   ```js
   new PerformanceObserver((l) => l.getEntries().forEach((e) => console.log('longtask', e.duration)))
     .observe({ entryTypes: ['longtask'] })
   ```
   做一遍主要操作，>50ms 的任务应为 0（重操作允许 1 次）。
2. **帧间隔**：录 Performance，看 Frames 轨道 P95；或 rAF 采样：
   ```js
   let last = performance.now(), gaps = []
   const tick = (t) => { gaps.push(t - last); last = t; if (gaps.length < 300) requestAnimationFrame(tick)
     else console.log('p95', gaps.sort((a,b)=>a-b)[Math.floor(gaps.length*0.95)]) }
   requestAnimationFrame(tick)
   ```
3. **主进程阻塞**：在主进程临时包一层计时（仅本地调试），确认没有 >16ms 的同步块。
4. **内存往返**：记录基线 → 切 10 次空间 → 空闲 5 分钟 → 再记录；renderer 进程数应回到基线，RSS 漂移 ≤5%。

### 13.3 关键路径专项

| 路径 | 观察点 |
| --- | --- |
| 切 space | 点击后首帧是否只有"新空间上屏"；旧标签是否延后消失 |
| 切标签（休眠标签唤醒） | 是否先出快照占位再出真实页；有没有白屏一帧 |
| 打开/收起浮层 | 收起后是否停止出帧；再次打开是否空白一帧 |
| 窗口 resize | 是否抖动；松手后是否二次跳变 |
| 媒体播放 | 帧率是否稳定；切后台是否降载 |

## §14 变更、回滚与登记

1. **一次改动一件事**：性能改动与功能改动分开提交，便于单独回滚。
2. **必须写净账**（G4）：`净减少 …/净新增 …`；净新增常驻开销默认拒绝。
3. **必须登记**：本文 §10 台账 + [PART18 §2 索引](5-文档地图与工程红线.md) 各一行。
4. **回滚优先**：出现"该亮的没亮 / 该睡的没睡 / 跨空间串档"这类**正确性**问题，先回滚再分析，不带着问题继续优化。
5. **反面教材存档**："静音媒体也回收"——增加了每次判定的常驻开销，收益不足以抵消，已回滚；后续不得以任何形式重做。
6. **日期标注**：本文条目变更需注明日期，避免读者误读旧结论。
