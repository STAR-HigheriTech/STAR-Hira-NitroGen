## 0. 共同地基（先看清楚，四项都架在它上面）

| 事实 | 位置 | 对本设计意味着什么 |
| --- | --- | --- |
| 每 profile 一个独立持久 Session | `infra-window/src/SessionsController.js`（`session.fromPath`） | **N10 的隔离底座是现成的**，不需要新造 |
| `WebContentsManager` 按 `profileId` 解析会话（可注入端口） | `WebContentsManager.js#_resolveSession` / `#_resolveTabProfile` | 只要 tab 记录带上"身份 profileId"，会话自动正确 |
| tab 记录已有 `profileId` / `spaceId` | `TabManager.js`（`_projectTab`） | 容器标签只需再加一个 **`containerProfileId`** 覆盖"身份"，`profileId/spaceId` 继续表示"归属" |
| 事件推送：主进程 → 页面 preload | `main.js`：`` wc.send(`ngipc:event:${IPC_EVENTS.x}`) ``；preload 侧 `ipcRenderer.on('ngipc:event:x')` | 浮层/开关都能走这条线，**零 layout / vite / 路由改动** |
| 键位表 `before-input-event` 目前**只吃 keyDown** | `main/keybindings.js#handleInputEvent` | A6 的"按住 Ctrl+Tab 弹浮层、松手提交"需要补一条 keyUp 通道 |
| 页面侧已有"注入阴影 DOM 覆盖层"的成功范式 | `preload/gestures/index.js` | A6/D5 的浮层直接复用这个范式（不做新的原生浮层视图） |

**为什么 A6 / D5 的浮层走页面 preload 而不是原生浮层视图**：原生浮层（`FLOAT_NAMES`）每加一个要同步改
4 处（layout 表 / electron.vite 输入 / IPC 契约 / 路由注册），而这两个浮层都只要求"盖在当前网页上、
居中显示"——页面侧 shadow DOM 用 `position:fixed + z-index:max + pointer-events:none` 就能满足，
且已有 `gestures` 证明可行。**成本差一个数量级，收益相同。**

## 1. N9 · 空间导航（键盘在可点击元素间跳转）

**是什么**：方向键在网页上按**几何位置**跳焦点（不按 DOM/Tab 顺序），Opera/Vivaldi 的 Spatial Navigation。

**落点**
- 纯算法：`packages/shared-types/src/spatial-nav.mjs#pickSpatialTarget(candidates, current, dir)`
  - 候选：`a[href], button, input, select, textarea, [tabindex], [role=button|link]`，过滤不可见 / disabled / `tabindex="-1"`。
  - 判据（业界通用）：只取**目标方向那一侧**的矩形；方向轴上距离为主，**侧向偏移**为罚项（投影重叠时罚 0）；
    取 `主距 + 0.5 × 侧偏` 最小者。无当前焦点时从**视口中心**出发。
- 注入引擎：`infra/infra-window/preload/spatial-nav/index.js`
  - 开关来自设置 `input.spatial_navigation`（**默认关**：方向键默认必须还是滚动）。
  - 捕获阶段 `keydown`：开 + 方向键 + 无修饰键 + 焦点不在可编辑元素 → 移动焦点。
  - 移动后 `focus({preventScroll:true})` + `scrollIntoView({block:'nearest'})`。
- 开关下发：主进程 `settings:changed` → `webContents.getAllWebContents()` 广播
  `ngipc:event:input:spatial-nav`；preload 启动时也 `invoke` 一次（两处兜底，任一失效都不会失灵）。
- 设置项：`input.spatial_navigation`（toggle，section「输入」）。

**接入面**：设置项 ✅ + 页面直接生效 ✅（满足准入项 14）。

## 2. D5 · Break Mode（番茄钟 / 全屏专注）

**是什么**：进入专注态，**盖住网页**显示倒计时 + 鼓励语；专注段结束自动转入休息段。

**落点**
- 控制器：`apps/app-main/src/main/break-mode.js`
  - 应用级单例（专注是全局的，不该每个窗口各算各的）。
  - 两个阶段：`focus`（默认 25 分）→ `break`（默认 5 分）→ 结束。
  - 状态机：`idle | running | paused`，`tick` 每秒；剩余时间广播给**每个浏览器窗口的活动标签**。
  - 退出：手动（快捷键 / 浮层按钮）或专注段走完（自动进休息，休息走完自动收）。
- 浮层：`infra/infra-window/preload/break-overlay/index.js`（与 gestures 同款 shadow DOM 覆盖层）
  - 半透明深色遮罩 + 居中大号倒计时 + 阶段名 + 鼓励语 + 「跳过 / 暂停 / 退出」。
  - 遮罩**吃指针**（它就是用来挡住网页的）；按钮回传 `ngipc:invoke:break:control`。
- 命令 / 快捷键：`view:toggle-break` = `Ctrl+Alt+B`（并入既有动作表，于是自动化页/命令链/手势都能编排它 —— 零成本多三个接入面）。
- 设置项：`break.focus_minutes` / `break.break_minutes` / `break.message`（section「专注」）。

**接入面**：快捷键 ✅ + 动作表（命令链/手势可编排）✅ + 设置项 ✅ + UI 载体 ✅。

## 3. A6 · MRU 标签切换器

**是什么**：`Ctrl+Tab` 按住弹浮层，按**最近使用顺序**列出标签；连按 `Tab` 循环，松手跳到高亮项。

**落点**
- MRU 数据：`TabManager` 的 tab 记录新增 `lastActiveAt`（激活时刷新，初始化取创建时刻）；
  `_projectTab` 透出它；新增 `listMru(scope)`（按 `lastActiveAt` 降序）。
- 纯算法：`packages/shared-types/src/tab-mru.mjs#orderByMru(tabs, activeTabId, limit)`
  —— 当前标签恒在首位（`Ctrl+Tab` 的第一次移动落到"上一个用过的"，与 Chrome/Edge 一致）。
- 主进程控制器：`apps/app-main/src/main/mru-switcher.js`（**每窗口一个**，由 `browser-window-runtime` 持有）
  - `step(dir)`：首次调用 → 取 MRU 序 + `index = 1`；再调用 → `index ± 1`（环绕）；每次都把
    `{ open, items, index }` 推给活动标签的 preload。
  - `commit()`：切到 `items[index]`，收起浮层。
  - `cancel()`：收起，不切。
- 键位：`tab:next`（`Ctrl+Tab`）/ `tab:prev`（`Ctrl+Shift+Tab`）改由切换器驱动：
  - keyDown → `step(+1 | -1)`
  - keyUp（松 Ctrl 或松 Tab）→ `commit()`；`Esc` → `cancel()`
- 键位表扩展：`main/keybindings.js` 新增可选端口 `onKeyUp(event, input)`（**只对 keyUp 直达**，内置动作表不受影响），
  由 APPS 装配时注入 —— 这是本轮唯一对 infra 共享模块的改动，且是**纯增量**（不传就与现在完全一样）。
- 浮层：`infra/infra-window/preload/mru-overlay/index.js`（同 gestures 范式）
  - 居中卡片，最多列 9 项：序号 + favicon + 标题；当前高亮。

**接入面**：快捷键 ✅ + UI 载体 ✅（`Ctrl+Tab` 原语义被升级，不新增第二套切换）。

## 4. N10 · 容器标签（同窗口内用别的 profile 身份开一个标签）

**是什么**：在当前空间里开一个**属于另一个 profile 身份**的标签 —— cookie/存储走那个 profile 的 Session，
**但不切换当前空间**。这正是不做「整空间切换」的 per-tab 多账户。

**关键模型（必须写清楚，否则必然写歪）**

| 字段 | 含义 | 容器标签的取值 |
| --- | --- | --- |
| `profileId` / `spaceId` | **归属**：这个标签出现在哪个空间/列表里 | 仍是**当前** profile/space |
| `containerProfileId` | **身份**：用哪个 Session（cookie 等） | = 被选中的那个 profile |

> 于是 `_orderedEntriesInSpace(profileId, spaceId)` 不变（标签照常出现在当前空间），
> 而会话解析改用身份 —— 这就是"不切空间也能用另一个身份"的全部秘密。

**落点**
- `TabManager`：`newTab({ containerProfileId })`；记录带该字段；`_projectTab` 透出 `containerProfileId`。
- `WebContentsManager#_resolveTabProfile`：**优先返回 `containerProfileId`** 作为 profileId。
  （创建与"休眠后重建"两条路都走这里，所以两处自动一致 —— 不必各改一遍。）
- UI 入口：标签右键菜单（`ui/ui-common/src/tabContextMenu.ts`，唯一实现，三处列表共用）新增
  「以「<身份名>」的身份打开」—— **一条身份一项、平铺**（该菜单模型没有子菜单），
  由宿主注入 `listContainerProfiles(tab)`（返回 `[{id,name}]`）+ `onOpenInContainer(tab, profileId)`。
  列表为空（只有一个 profile）时**整段不出现**（S4：不留点了没反应的项）。
- 标识：标签行加 `container` 类 → **顶边一条身份色带**（Firefox Multi-Account Containers 的手法）。
  走 `::before` 而不是新增 DOM 子节点：标签内部间距由 `tabSizing` 按固定几个孩子压缩计算，
  中间插元素会在窄标签下把标题挤没；而 `::after` 已被 favicon 取色指示线占用，两者必须各用各的。
  三处列表（横向标签条 / 纵向标签列 / 面板）共用 `ui-tabbar/components/Tab.js` 这一个渲染件，故一次到位。
- 数据来源：`profile:list`（已有）。颜色沿用 profile 的 `color`（色带默认走 `--container-color`，回退强调色）。

**接入面**：右键菜单 ✅ + tab 行标识 ✅ + 设置/数据（复用既有 profile）✅。
