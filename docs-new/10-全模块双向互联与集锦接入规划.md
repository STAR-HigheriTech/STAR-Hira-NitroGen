## 第一部分 · 什么叫"双向接入"（先把判据定死）

**单向（会耦合）**：我调用你。比如集锦直接 `require` 书签面板。
**双向（本次目标）**：两个模块**既能作为源、也能作为目标**，且都走窄接口。三面齐全才叫双向：

| 面 | 作用 | 本项目现成机制 | 例子 |
| --- | --- | --- | --- |
| **暴露面**（我让别处往我这里加） | 别的模块**挂到我身上** | **29 个官方插槽**（extension points） | `webview.context-menu.item`、`side-panel.toolbar-action-slot` |
| **通知面**（我知道别处发生了什么 / 别处知道我这里发生了什么） | **事实广播**，而非轮询 | `ngipc:event:*`（`note:changed`/`tab:changed`/`bookmark:changed`）+ 窗口级事实（`overlay:modal`、`layout:side-column-float`） | 集锦变了 → 面板重画；拖拽让位 |
| **受控面**（别处能让我做一件事） | **动作可被任意入口触发** | 动作命名空间：`keybindingActions` / `TabManager#omniboxAction` / **bangs** / `chain:<id>` | 手势、命令链、快捷键、地址栏 `!save` 都调**同一个**动作 |

**铁律（否则"互联"立刻变"耦合"）**：
1. **依赖方向永不反转**：`ui → apps → infra → domain`。互联**只能**经上面三条窄接口 + 端口注入（`ctx.clients.*`）。
2. **一份真源**：插槽表 / 事件表 / 动作表 / 菜单 kinds 表，加一项 = **加一行**，不许第二处再写一遍。
3. **互联是显式动作，不是自动同步**（同族数据永不同步两份）。
4. **一个新功能必须同时回答两个问题**：① 我作为**源**，别处怎么用我？② 我作为**目标**，我怎么接收别处？答不出②的就是单兵作战。

### WP1 · 动作层统一（**受控面**）—— 消灭"每个入口各写一份" ✅

> 已实现：九条动作收在 `main/note-actions.js`（`actions` 无参表 + `run(action, params)`），
> 由 `main.js#keybindingActions` / `TabManager#omniboxAction`(`note:` 前缀) / `commands.mjs` /
> 应用菜单共用。附带解决了「面板本次才打开 → open-view 事件丢失」的竞态：
> `showPanel` 返回「事先是否已开」，未开时载荷落入按窗口的 pending 槽（5s TTL），
> 面板挂载后经 `note:take-open-view` 主动拉取（`panel-notes.renderer.js#applyOpenView`）。
把跨模块动作收成**动作命名空间**的正式成员（与现有 `tab:*` / `window:*` / `open_*` 同族）：

```
note:save-page        收当前页进集锦（带 folderId 参数）
note:save-tab         收某个标签（tag 右键 / 多选 / 拖放 都调它）

note:save-text        收选中文字

note:open-all         整集锦全部打开
note:copy-all         整集锦复制到剪贴板

```
- 落点：`apps/app-main/src/main/main.js#keybindingActions`（窗口级）+ `TabManager#omniboxAction`（地址栏/链）。
- 收益：**快捷键 / 手势 / 命令链 / bangs / 菜单 / 插件插槽 / 面板按钮 —— 七个入口共用同一实现**，

### WP4 · 事件层统一（**通知面**）—— 建立事件名册，禁轮询 ✅

> 已实现：新增 [event-catalog.mjs](file:///e:/Desktop/OTHER/1A-STAR_Hira/1A-STAR_Hira_NG/packages/shared-types/src/event-catalog.mjs)
> 作为**事件名册唯一真源**。73 条事件全部登记（键引用 `IPC_EVENTS.*`，路由改名时不会静默失配），
> 每条给出 `scope / payload / subscribers / note`。
>
> **作用域三分**：
> - `app` —— 应用级事实（settings / 书签 / 历史 / 笔记 / 下载 / 空间 / profile / 主题…），
>   不带 windowId，广播给所有订阅者；
> - `window` —— 窗口级事实（标签 / 分屏几何 / 窗口状态 / 当前空间 / 浮层让位…），
>   **必须带 windowId**，否则多窗口串台（`ui-shell` 直接渲染推送载荷）；
> - `target` —— 定向事实（浮层 / 某个 preload 引擎 / 发起方 renderer），主进程直接 `wc.send`，
>   登记它是为了标注归属，让"该不该广播"有据可查。
>
> **校验端口注入式接入**（infra 不反向依赖具体事件表，保持分层）：
> - `createBroadcaster(registry, { catalog, warn })` —— 投递前 `audit()`：未知路由、
>   `window` 级事件漏传 `windowId` 各告警一次（同路由只报一次，避免 16ms 事件刷爆控制台）；
> - `createListenerRegistry({ onUnknownRoute })` —— 渲染层**订阅**一条不存在的路由时同样告警，
>   专治「订阅了但永远收不到」的拼写错误；
> - 两条校验都只在 `!app.isPackaged` 时注入，生产态零开销；名册本身也能被面板直接
>   `eventSpec(route)` 查询（判断"我该不该在这个窗口里响应"）。
>
> **「禁轮询」现状**：真正需要"跟着别处变化"的宿主已全部改订阅（书签 / 历史 / 笔记 / TOTP /
> 扩展 / 插件 / 主题 / 设置 / 下载 / 空间 / profile / 权限）。现存 `setInterval` 均为设计性定时，
> 不是跨模块对账，逐个注明理由：
> - `download-controller` 15s 兜底 —— 仅为收敛无事件覆盖的带外变化；
> - `task-manager` 页面可见时才轮询；`theme-schedule` 分钟级定时换主题；
> - `break-mode` 1s 倒计时；`cursor-edge` / `tab-drag` / `split-toolbar` 主进程 30fps 采样式设计；
> - `js-dialog` 同步 poll-result 握手（零自旋）。
>
> 规矩：**新增一个面板/浮层要"跟着别处变化"，先查名册找事件；找不到就先登记一条，
> 再让发布方 emit —— 不许开定时器。**

### WP6 · 跨面板/跨视图拖放协议（**界面层**）—— 让面板之间互通 ✅

> **已实现**：一个协议真源 + N 个拖拽源 + M 个落点，彻底消灭「N 源 × M 落点」兼容矩阵。
>
> **真源** `packages/shared-types/src/drag-item.mjs`（零依赖，Node / 浏览器双端）：
> - MIME `application/x-hira-item`（JSON 载荷）；
> - `text/plain` 兜底，三档 `plain: 'url' | 'prefix' | 'none'`
>   （`none` 专供标签拖拽 —— 网页会把 text/plain 当搜索词接走）；
> - `getDragItem` 三级降级：MIME → 前缀编码的 text/plain → `text/uri-list` / http(s)；
> - `hasDragItem` 只读 `dataTransfer.types`（dragover 阶段可靠）；
> - `pickDropEffect`：把落点的「我想 copy」收敛到源端 `effectAllowed` 允许的集合内
>   （硬写 `dropEffect='copy'` 遇上 `effectAllowed='move'` 会让 drop 根本不派发）。
>
> **拖拽源**（统一写 `{ domain, id, kind, url, title, text, tabId, folderId }`）：
> 横向标签条 / 纵向标签列表（侧栏 · 打开标签 · 固定标签 · 悬停浮出，共用 `tabRowList`）/
> 集锦卡片与文件夹 / 书签栏 / 收藏面板 / 历史 / 下载 / 画板卡片（按住类型色点上膛）。
>
> **落点**（按 `domain` 分发，而不是按来源面板）：
> - 集锦：`panel-notes.model.js#captureDroppedItem` —— tab → 页面、url → 链接/图片、
>   `data:image/*` → 资产入库、其余 → 文本；落在文件夹行上则进该文件夹；
> - 画板：画布接收统一下落成 note / link / image 卡（世界坐标 = 指针位置）；
> - 标签条：`useDropController#onExternalDrop` —— 有 url 就开新标签，落点描述与内置拖拽同形
>   （tab / stack / strip，可被 `tabbar.drop-target` 插槽抢答）；
> - 纵向标签列表：`tabListHost` 默认 `newTab({url})`，四个宿主零改动；
> - 书签栏：有 url 就存成书签；
> - 全部落点都先给插件插槽一次抢答机会，插件返回真值则宿主语义不执行。
>
> **标签条命中范围**：外部分支在 document 级监听上先判 `#tabs` 矩形 —— 否则把便签拖回
> 集锦自己身上也会被当成「要开新标签」。外部拖拽没有 dragend 兜底，因此 dragover 一旦
> 离开矩形就收线（否则指针移进页面内容后会留下幽灵插入线）；`showIndicator` 幂等写入，
> 高频 dragover 下不重复触发样式重算。
>
> **effectAllowed 口径**：既是条内排序、又可能拖到别处的源（标签条 / 纵向列表 / 集锦卡片 /
> 书签栏 / 收藏面板）统一声明 `copyMove`；只出不排的源（历史 / 下载 / 画板）声明 `copy`。
>
> **剪贴板式兼容**：外部浏览器拖来的普通链接（`text/uri-list` / 纯 http 文本）也走同一条
> 通道落进集锦 / 画板 / 书签栏，无需专门分支。
>
> **已有基础**（保留）：`tabbar.drop-target` 插槽 + `dropzone-overlay` + app-shell 的拖拽让位
> （`.vtabs--vists--drag-yield`）。

## 第四部分 · 判据与红线（防止"为了互联而耦合"）

**新增功能前的 4 问**（缺一即单兵作战）：
1. 我的数据/能力**作为源**，有哪几条窄接口给别人用？（插槽 / 事件 / 动作）
2. 我**作为目标**，怎么接收别人的东西？（右键项 / 拖放 / 端口）
3. 我加的这一项，是否只在**一张真源表**上加了一行？
4. 我是否引入了新的依赖方向？（必须回答"没有"）

**明令禁止**：
- ❌ 面板/浮层直接 `import` 另一个面板/浮层的实现（跨面板一律经 ports 或事件）。
- ❌ 用轮询替代事件；用第二份表替代真源表。
- ❌ 同一动作在多个入口各写一份实现（WP1 就是为消灭它）。
- ❌ 自动同步两个同族数据（书签↔集锦、归档↔集锦只能显式搬运）。
- ❌ 为"互联"把两个域互相 require（要互联就加事件或动作，不加依赖）。

| 想做的事 | 用哪条接口 | 真源文件（加一行的地方） |
