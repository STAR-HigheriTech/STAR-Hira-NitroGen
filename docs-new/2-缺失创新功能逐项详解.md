# 一、标签与视图编排

## A1 · Glance 速览

**这是什么**
在当前网页之上，盖一张**略小的"卡片"**，让你快速看一眼某个链接/标签的内容；不想看了随时收起，回到原来那一页——全程不新开标签、不丢当前上下文。

**怎么玩**
右键一个链接（或标签）→「速览」。新页以 **85% 宽的卡片**浮在当前页上方，后面的原页露出边缘、像被压在下面。按 `Esc` 或点卡片外收起；再点一次可把速览"提升"成正标签。
真正的形态是**两态叠放**：`front`（前面的）宽 85%、高 100%；`back`（后面的）宽 95%、高 97.5%——都相对内容区居中，于是看起来就是"一叠卡片"，前面的略小、后面的略大。

**对标产品怎么做**
- Zen：招牌功能，叫 Glance；常在侧栏/右键触发。
- HiraRT：`src/main/controllers/tabs-controller/tab-groups/glance.ts` + `tab-layout.ts#calculateGlanceBounds`——**成员恒为 2**（`new Set(tabIds).size !== 2` 就自动解散），并各占一个视图层 `TAB_BACK(9)` / `TAB_FRONT(10)`。

**为什么算创新**
普通浏览器"看个链接"= 开新标签 → 看 → 切回来，三步且污染标签栏。Glance 把"看一眼"变成**零成本**：不产生标签、不动历史、一个手势来回。

**NG 现状与落点**
❌ 无实现：全库 `glance` 在 `apps/` 0 命中，只有 `docs/vertical-tabs-design.md` 提过设计。
落点（沿用四层，不新增架构）：`domain/domain-tabs/TabGroups.js`（纯几何，算法见上）→ `TabManager` 加 `createGlance/setGlanceFront/dissolveGlance` + 关闭/切换/休眠/撤销关闭四处钩子 → `LayoutCoordinator.showGlance/hideGlance`（前台走弹簧/缓动、后台直落）→ 3 条 typed IPC（`tab:glance-*`）→ 入口 `tabbar.context-menu-item`。

## A2 · 标签自动归档区

**这是什么**
未固定的标签闲置超过设定时间就**自动收进"归档区"**（不再占标签栏，但随时能翻出来）；固定标签永远保留。类似邮箱的"归档"而不是"删除"。

**怎么玩**
设置里选归档阈值（NG 已有：`never / 12h / 1d / 7d / 30d`）。到点后标签从标签栏消失、进入一个"归档"入口；点归档项可恢复成正常标签。Arc 还会把归档按时间分组展示。

**对标产品怎么做**
Arc：pinned 标签永久保留，其余标签到点自动 archive；同一入口还能 `⌘Z` 撤销。

**为什么算创新**
浏览器越用标签越多，最终标签栏挤成一团。归档把"我不想关、但也不看"的标签**自动收纳**，标签栏始终清爽，又不丢东西。

**NG 现状与落点**
🟡 半成品：引擎已有 —— `infra/infra-window/src/tabLifecycle.js`（`archiveTab/archiveInactive`）+ 设置 `tabs.archiveAfter`。**缺的是"归档区"面板/入口**（归档后去哪看、怎么恢复）。
落点：新增面板插件 `panel-archive`（manifest 里 `contributes.panels` 一行）＋ `domain-session` 存归档元数据；列表复用 `ui-common#createTabListHost`。

## A4 · Pin Grid / Slot Machine

**这是什么**
把"固定标签"从**一条横条**变成**一页网格**：每个固定标签是一张大卡片；还有个"老虎机"式玩法——一拉，把某个固定标签关联的一批标签**一次性批量打开**。

**怎么玩**
固定标签区切成网格排列（每格一个站点大图标/缩略图）；hover 显示预览；点击打开。Slot Machine：像拉老虎机，滚轮/拖动选中一组，松手全部打开。

**对标产品怎么做**
HiraRT：`src/renderer/src/components/browser-ui/browser-sidebar/_components/pin-grid/`（`pin-grid.tsx`、`slot-machine/main.tsx`、`find-closest-pin-edge.ts`、拖拽排序动画）。

**为什么算创新**
固定标签一多，横条就放不下、只能显示图标。"网格 + 批量打开"把常用站点变成一块**可扫视的仪表盘**，比横条信息密度高得多。

**NG 现状与落点**
❌ 无（NG 有固定标签 + `ui-panel-pinned` 面板，但没有网格化与批量打开）。
落点：新 `ui/ui-pin-grid` 包，挂 `side-panel.panel-render-slot`；数据复用 `domain-tabs` 的 pinned。

---

## A5 · 跨窗口标签同步

**这是什么**
让多个窗口**共享同一份标签集合**：把窗口视作"显示器"，而不是"各装一套标签"。当你在 A 窗口操作，B 窗口能同步看到同样的标签；关闭某个窗口时它的标签**迁移**到还在的窗口，而不是被销毁。

**怎么玩**
设置里打开"跨窗口同步"。切到哪个窗口，活动标签的**真实视图就移动到那个窗口**，原窗口留下**一张截图占位**（避免"移动"时出现空白/闪烁）。

**对标产品怎么做**
HiraRT `src/main/controllers/tabs-controller/tab-sync.ts`：默认关闭；窗口获焦时把活动 tab 的 `WebContentsView` 移过去、旧窗留 `capturePage` 截图；用**代际计数器**防 OS 聚焦抖动导致"陈旧移动"，用**串行变更队列**防并发竞态；内部/隐身/弹窗标签被排除。

**为什么算创新**
多显示器用户的痛点：每个窗口各自一堆标签，乱。同步后"所有窗口看到的是同一组标签"，只是物理显示器不同——概念上干净非常多。

**NG 现状与落点**
❌ 无持续同步：NG 只有"拖拽迁移"（`main/tab-drag-controller.js`，用 `CursorEdgeMonitor` 采样屏幕光标，拖到别的窗口标签栏就迁移）。
落点：新 `infra/infra-window/src/TabSync.js`（代际计数器 + 串行队列 + 截图占位，协议复用 `hira://tab-snapshot`）+ 设置 `tabs.sync_across_windows`。

## A6 · 标签 MRU 可视化切换器

**这是什么**
按 `Ctrl+Tab` 时弹出一个**可视化浮层**，按"最近使用顺序"列出标签缩略图，按住不动可循环选择，松手切换。不是简单地切到"下一个标签"。

**怎么玩**
按住 `Ctrl` 连按 `Tab` → 浮层出现并高亮下一项；松手跳到高亮标签。也可 `Ctrl+Shift+Tab` 反向。

**对标产品怎么做**
Zen、Vivaldi（"Tab Cycler"）都有；按使用频率/最近使用排序，比纯顺序更贴直觉。

**为什么算创新**
标签一多，"下一个标签"经常不是你要的那个。MRU + 缩略图让切换**有预览、可预期**。

**NG 现状与落点**
🟡 只有基础 `Ctrl+Tab` 顺序切换（`keybindings.js` 的 `tab:next/tab:prev`），无可视化浮层。
落点：纯渲染层插件，挂 `layout.root-slot`。

# 二、空间 / 工作区

## B1 · 每空间主题 / 壁纸 / 强调色

**这是什么**
让每个"空间"有**自己的外观**：背景、壁纸、强调色都不一样。切空间时整个浏览器"换装"，帮助你在心理上区分"这个空间是工作、那个是娱乐"。

**怎么玩**
编辑空间时挑背景（纯色/渐变/图片）、强调色；切空间时界面随之变色。

**对标产品怎么做**
Zen/Arc：每个 workspace 有主题色/图标/渐变背景。HiraRT：空间带 `bgStartColor/bgEndColor` 渐变。

**为什么算创新**
空间不只是"标签分组"，更是**上下文切换的视觉锚点**——一眼就知道自己在哪个空间。

**NG 现状与落点**
🟡 部分：空间已有渐变字段（`domain-space` 的 `bgStartColor/bgEndColor`）+ 图标，但**没有把主题随空间切换**。
落点：`profile.on-before-switch` / `on-after-switch` 插槽（已存在）+ `theme.source`。

---

## B2 · 空间级独立设置

**这是什么**
同一套设置里，**每个空间可以有自己的值**：主题、代理、UA、书签顺序…A 空间开代理、B 空间不开。

**怎么玩**
设置页里某些项标记为"按空间"，每个空间各存一份；也可"从当前空间复制到新空间"。

**对标产品怎么做**
Zen/Arc：workspace 携带自己的偏好。

**为什么算创新**
"工作空间"要真正可用，就得连**环境变量**都能隔离，否则切空间只换了标签，环境还得手改。

**NG 现状与落点**
🟡 **已有 per-profile 覆盖层**：`domain/domain-settings/src/profileOverlay.js`（Steam 式按 profile 覆盖、读写落盘、`list()` 合并 base+overlay）。
缺的是"同一 profile 内多空间"的差异化 + 设置 UI 入口。落点：在 `profileOverlay` 上扩展 + `space.settings-provider` 插槽。

---

## B3 · 空间导出 / 导入

**这是什么**
把某个空间（含它的设置与标签）**打包导出成文件**，换机/备份时再导入。

**怎么玩**
空间菜单 →「导出」生成一个文件；另一台机器「导入」→ 还原成一个空间。

**对标产品怎么做**
Vivaldi（会话保存/同步）、Arc（Spaces 可分享）。

**为什么算创新**
空间是用户的"资产"。能导出=能备份、能迁移、能分享一套配置。

**NG 现状与落点**
❌ 无（`domain-space` 只有 CRUD，无导出/导入）。
落点：新命令 + `domain-space` 端口；入口走设置页 `settings.section-renderer`。

---

## B4 · 空间快捷键

**这是什么**
用键盘直接切空间，比如 `Alt+1 / Alt+2`。

**对标产品怎么做**
HiraRT 用 `Ctrl+1..N` 切空间。

**NG 现状与落点**
❌ **且与现有键位冲突**：`Ctrl+1..9` 已被 `tab:1..tab:9`（切标签）占用（`keybindings.js` 默认表）。必须另择键位（如 `Alt+1..N`）。
落点：`keybindings.js` `DEFAULT_KEYBINDINGS` 增项 + `space-controller`。

---

## B5 · 公共 / 共享空间（协作）

**这是什么**
把空间**分享给别人**，多人看到同一组标签/链接，甚至能实时协作。

**对标产品怎么做**
Arc 的 Shared/Public Spaces（需账号与后端）。

**NG 现状与落点**
❌，且**需后端**。当前不建议自建，列为可选远期。

# 三、站点定制与内容增强

## C1 · Boosts 站点定制（Arc 招牌）

**这是什么**
为**某个网站单独注入 CSS/JS**：改它的颜色、字体、隐藏碍眼的元素（"Zap"），甚至写脚本。每个站点一套规则，互不影响。

**怎么玩**
在页面上点"Boost" → 出现一个面板：调色（自动从页面主色派生配色）、选字体、开关"Zap 模式"（点哪个元素就隐藏哪个）、写自定义 CSS/JS。保存后每次访问该站自动生效，可随时开关。

**对标产品怎么做**
Arc 最出圈的功能，叫 Boosts；配套有"从页面取色、一键换配色、隐藏元素"的可视化编辑。

**为什么算创新**
它把"用户脚本/油猴"的能力**做成了可视、零门槛**的站点级定制：不用写代码也能把某个常去的网站改成自己喜欢的样子。

**NG 现状与落点**
❌ 无（全库 `boost` 0 命中）。
落点：新 `domain-boost`（站点→规则存储）+ 注入走 `webview.lifecycle.will-navigate`（REDUCE，已存在）或新增 `webview.injected-style`；UI 用 `webview.context-menu.item` + 新面板。

---

## C2 · UserScripts 用户脚本

**这是什么**
像 Tampermonkey 一样，装/写脚本去增强或改造网页（去广告、加功能、改样式）。比 Boosts 更"硬核"，是给会写 JS 的人用的。

**对标产品怎么做**
旧 Hira 有 `js/userscripts.js`；主流靠扩展（Tampermonkey）。

**为什么算创新**
内置后无需装扩展就能跑脚本，且可与 C1 Boosts **共用同一条注入通道**。

**NG 现状与落点**
❌ 无（NG 无 userscripts）。
落点：同 C1 的注入通道；管理器做成 `panel-userscripts` 插件。

---

## C3 · 网页翻译引擎

**这是什么**
把外文网页**整页翻译成你的语言**，或选中一段翻译。

**对标产品怎么做**
Vivaldi/Chrome 内置翻译；Zen 也有。可在线（Google/DeepL）或**离线**（本地模型）。

**为什么算创新**
隐私友好的**离线翻译**是差异点——页面内容不出本机。

**NG 现状与落点**
🟡 只有设置项：`settings/registry.js` 的 `languages.translate_pages` / `target_language`，分区说明明写"**当前尚未接入翻译引擎**"。
落点：新 `domain-translate` + 新增插槽 `translate.provider`；引擎可接 `@browsermt/bergamot-translator`（**已在 package.json 依赖里**）。

---

## C5 · 自定义搜索引擎

**这是什么**
自己**添加搜索源**（比如公司内网搜索、某个小众引擎），并给它设快捷关键字。

**怎么玩**
在设置里加一条"名称 + 搜索 URL 模板 + 关键字"；地址栏输入关键字即可用该引擎搜。

**对标产品怎么做**
Vivaldi（可加任意引擎）、Chrome（"网站搜索"）；旧 Hira 有 `registerCustomBang`。

**为什么算创新**
NG 现在只有**内置** bangs；用户不能加自己的。企业/垂直搜索场景需要它。

**NG 现状与落点**
❌ 无自定义（`domain-search` 只有内置 bangs）。
落点：`domain-search` 小扩展 + 设置分区；结果并入 `search.suggestion-provider`（已存在）。

---

## C6 / N16 · 整页 / 选区截图

**这是什么**
把**整页**（含滚动到的所有内容）或**框选的一块**截成图片，直接保存/复制/标注。

**怎么玩**
右键或工具栏 → 截图 → 选"整页 / 可见区域 / 框选"；可进入简单标注（箭头/马赛克）再保存。

**对标产品怎么做**
Vivaldi Capture；Edge 网页捕获。Vivaldi 还能全页 + 选区（快照/贴图）。

**为什么算创新**
高频实用工具。NG 已具备**截帧能力**（只是服务于标签缩略图），把它暴露成用户功能成本极低。

**NG 现状与落点**
❌ 无用户功能：`capturePage` 存在于 `infra-window/src/SnapshotStore.js` / `WebContentsManager.js` / `TabManager.js`，但只用于标签缩略图；全库 `screenshot` / `fullPageCapture` 0 命中。
落点：复用 `capturePage` + 新 `panel-capture` 插件；整页需滚动拼接。

---

## C7 · 周期性自动刷新

**这是什么**
让某个标签**每隔 N 秒自动刷新**，用于盯盘、抢票、看后台状态。

**对标产品怎么做**
Vivaldi"周期性重载"。

**NG 现状与落点**
❌ 无（`periodic` 相关无实现）。
落点：`tabbar.context-menu-item` 加一项 + `domain-tabs` 记定时器。

# 四、命令与自动化

## D1 · 命令面板（Quick Commands）

**这是什么**
一个**万能搜索框**：打字就能执行浏览器里的任何命令（新建窗口、切主题、开设置、跑某个动作…），也能搜标签/历史/书签。键盘流的核心入口。

**怎么玩**
按快捷键（如 `Ctrl+Shift+P`）→ 输入 → 回车执行。

**对标产品怎么做**
Vivaldi 的 Quick Commands；HiraRT 的 Omnibox 就是命令面板；Arc 的 Command Bar。

**为什么算创新**
把"藏在各菜单里的操作"变成**可搜索、可键盘直达**，熟练用户效率是菜单的几倍。它还是后面 **D2 命令链**的地基。

**NG 现状与落点**
❌ 无（全库 `commandPalette` 0 命中；NG 曾实现又移除）。

# 五、组织与检索

## E1 · Chromium 式历史模型

**这是什么**
把历史记录做成**"网址表 + 访问记录表"双表**：同一个网址访问多次只存一行 URL，但每次访问都留一条 visit（带时间）。还能区分"地址栏输入"（`typed_count`）和"点链接"，并按时间保留 N 天后自动清理。

**对标产品怎么做**
HiraRT：`design/chromium-inspired-browsing-history.md`——`history_urls`+`history_visits` 双表、`typed_count`、连续同 URL 去重、YouTube 归一化到视频 id、90 天保留、仅记活动标签与 http(s)、跳过隐身。

**为什么算创新**
NG 现在是**单行 upsert**（`domain-history` 只把 `visitCount` 自增、更新时间），无法回答"我上周二下午看了什么"，也无法按"我主动输入的"排序做地址栏建议。双表模型对这些都自然支持。

**NG 现状与落点**
🟡 简化模型：`domain/domain-history/src/history-service.ts`（`visitCount` 自增 + `lastVisitAt`）。
落点：扩 schema + 迁移走 `db.schema.migration` 插槽（已存在）。
