# 9 · Edge「集锦（Collections）」完整剖析 × NG 笔记功能融合方案

> 目的：把 Edge 集锦**全部功能与细节**摸清，再回答「引入 NG 时怎么处理与 Note 的重叠」——
> 结合 / 取舍删一个 / 融合 / 并存，四选一由本文给出结论与可照做的落地设计。
>
> ⚠ **参照标准（唯一）**：**Edge ≤144 的经典「完全体」集锦** —— 145 之后微软逐步下线、
> 149 起彻底移除，但它是口碑最好、支持率最高的一版。**本文以它为复刻目标，不因"微软已经删了"
> 做任何功能裁剪**；微软那套"只搬 URL、丢掉图片与备注"的迁移方式只作**反面教材**。
> 逐项对照与档位（完全一致 / 等价实现 / 降级 / 不适用）见**第八部分**。
>
> 事实来源：微软官方支持文档与学习中心（见文末 Sources）+ NG 仓库现状盘点（带文件路径与行号）。

## 第一部分 · Edge 集锦完整剖析

### 1.1 结局先行：这个功能在 Edge 里已经死了（对我们最重要的一条事实）

| 时间 | 事件 |
| --- | --- |
| 2022 | 微软把 **阅读列表（Reading list）并入集锦**（独立入口消失） |
| Edge 145 | **不能再向集锦添加新页面**；已有集锦仍可访问；面板里弹通知引导迁移 |
| **Edge 149（2026-06-04 发布）** | **集锦在 Edge 中彻底不可用** |
| 2025-11 起 | 集锦上挂着的"购物"能力（价格比较/历史/跟踪/返现）整体并入 Copilot |

微软给出的三条迁移路径，以及它们各自的代价：

1. **一键「移动到收藏夹」**（推荐）：集锦 → 收藏夹根下的文件夹。**只搬保存的网页 URL；
   图片、备注、以及其它非页面项全部不搬。**
2. **导出数据**：**仅 AAD（工作/学校账号）可用**；个人账号看不到这项。
3. **个人账号**：内容仍可在 `bing.com/saves` 查看（从 Edge 侧不能再新增）。

> **两条关键教训（直接决定我们的选择）**
> 1. 微软自己对这个重叠的答案是 **"并进收藏夹"** —— 即"不并存、合并"。（他们走的是"融合"路线。）
> 2. 但他们融合得**很粗暴**：只保留 URL，丢掉图片与备注。而"图片 + 网页片段 + 备注混排"
>    恰恰是集锦唯一不可替代的价值。**他们失败在合并方式，不在合并方向。**
>    → 我们若做，必须"连内容一起搬"；若做不到，就干脆别叫集锦。

### 1.2 集锦到底是什么（定位，与书签的边界）

**书签 = 一个 URL 占一个位置，为"长期导航"服务。**
**集锦 = 围绕一个主题/项目的「卡片板」，为"当下这件事"服务。**

集锦的核心不是"存 URL"，而是**四种异构卡片同列混排**（这一点极其关键）：

| 卡片类型 | 卡片内容 | 录入方式 |
| --- | --- | --- |
| **网页 page** | 标题 + URL + favicon（可编辑描述） | 「+ 添加当前页面」/ 右键「添加此页到集锦」/ 拖链接 |
| **图片 image** | 图片本身（缩略/原图）+ 源链接 + 源标题 | 悬停图片出现虚线框后**拖入面板** / 图片右键「添加到集锦」 |
| **文本片段 snippet** | 选中的那段文字 + 源链接 + 源标题 | 选中 → 浮动工具栏「添加到集锦」/ 拖入 / 右键 |
| **备注 note** | 富文本（字体 / 项目符号 / 标题） | 「添加备注」按钮 / 面板内右键「添加备注」；**仅桌面端可加** |

> 注意第 4 行：**备注和网页卡片躺在同一个列表里、都能拖拽排序**。等价于说——
> "笔记"与"集锦卡片"在 Edge 的模型里**本来就是同一种东西**，只是 `type` 不同。
> 这就是本文方案 C（融合）成立的**模型级依据**，而不是我们的偏好。

### 1.3 完整功能清单（逐项，含交互细节）

**A. 集锦的生命周期**
- 新建：面板顶部「启动新集锦」→ 输入名字（回车确认）。
- 重命名：**直接点面板顶部的标题**就地改。
- 切换/总览：面板左侧是集锦列表，点一个进一个。
- 删除：集锦的三点菜单 → 删除（**不可撤销，无回收站**）。
- 跨集锦移动：卡片右键「移动到」→ 选目标集锦。

**B. 内容录入（4 条路径 × 4 类卡片，Edge 的全部入口）**
1. 面板内「+ 添加当前页面」——整页收成卡片。
2. 页面右键「添加此页到集锦」→ 再选集锦（**跳过打开面板**）。
3. 页面里选中文字 / 图片 / 超链接 → 右键「添加到集锦」→ 选集锦。
4. 面板开着时**拖放**：拖图片、拖链接、拖选中的文字进去；**支持一次多选批量拖入**。
5. 选中文本后的**浮动工具栏**里也有「添加到集锦」。

**C. 卡片级操作**
- 编辑：三点菜单 → 编辑 → 可覆盖原标题、可改描述。
- 删除：三点菜单 → 删除（不可撤销）。
- 排序：**拖卡片上下移动**（桌面）；iOS 走"编辑"模式；Android 走显式「重新排序」模式。
- 多选：卡片右上角**复选框** → 选中后可批量「发送到 Excel / Word」。
- 单项分享：右键「复制」（复制整张卡片）/「复制链接」（只复制 URL）。
- 打开：右键「在新标签页打开」/「在新窗口中打开」；移动端直接点卡片。

**D. 集锦级操作**（面板右上「共享和更多」）
- **全部打开（Open all）**：把整集锦作为一组标签在新窗口打开。
- **复制全部（Copy all）**：整集锦的卡片文本复制到剪贴板（可直接粘进邮件）。
- **导出**：发送到 **Excel / Word / OneNote / Pinterest**（在目标 App 里自动新建文档）。
- 共享（复制给他人）。

**E. 跨端**
- MSA 登录后**跨设备实时同步**；桌面 / iOS / Android 三端；移动端可看、可加网页、**不能加备注**。

**F. 购物（Edge 特有包袱，已并入 Copilot，**不建议抄**）**
- 价格比较 / 价格历史图表 / 价格跟踪（降价提醒）/ 返现；现已全部由 Copilot 侧栏承接。

**G. 入口与快捷键**
- 工具栏「集锦」图标（堆叠卡片样式）；三点菜单 → **更多工具 → 集锦**；
- 快捷键 **Ctrl+Shift+Y** 唤出集锦面板。

**H. 数据与缺陷（推断 + 已知）**
- 存储：本地库 + 微软账号云同步（**内部表结构未公开，本文不做断言**）。
- 已知缺陷：① 迁移只搬 URL（丢图片/备注）；② 删除不可撤销；③ 移动端不能写备注；
  ④ 与阅读列表/收藏夹长期三足鼎立 → 最终被砍（**与书签的边界始终没讲清**）。

### 1.4 一句话总结 Edge 集锦

> 它把"**围绕一个主题收集四种异构卡片并同列编排**"这件事做到了极致，
> 但在产品侧**始终没解决与书签/阅读列表的重叠**，最后被自己合并掉。

## 第二部分 · NG 现状盘点（重叠矩阵）

### 2.1 NG 已有的"收集类"实体（全部 8 个）

| 实体 | 面板 / 载体 | 存储 | 存什么 | 与集锦重叠度 |
| --- | --- | --- | --- | --- |
| **笔记** | `notes-panel`（插件 `panel-notes`） | 表 `notes` + `note_folders`（SQLite，按 profile） | title + **content(markdown)** + url(来源页) + tags + color + pinned + folderId | **极高**：备注卡片 ✔、文件夹 ≡ 集锦 ✔ |
| **收藏** | `favorites-panel` | 表 `bookmarks` | url + title + favicon + folder + tags + pin(书签栏/rail) | 高（=网页卡片的"URL 版"） |
| **稍后读** | 笔记面板的一个**视图** | 同上（`notes` 里名为「稍后读」的文件夹） | url + title | 高（=网页卡片） |
| **画板 Easel** | `easel-panel`（面板 + 独立窗） | 设置键 `easel.boards` | 卡片三类 `note / link / image`（**image 为 dataURL 内联**）+ 笔迹 | **很高**：图片卡片 ✔ + 自由排布 |
| **归档区** | `archive-panel` | 设置键 `archive.entries` | url + title + favicon + spaceId + 时间 | 中 |
| **页面正文索引** | 无面板 | 表 `page_texts` + FTS5 | url + title + **正文纯文本** | 中（可作"摘要"来源，但生命周期绑 URL 裁剪） |
| **命名会话** | `hira://sessions` | 设置键 `sessions.named` | 一组标签 | 低 |
| **打开的标签页** | `open-tabs-panel` | 运行时 | 标签 | 低 |

### 2.2 关键结论（三条，决定方案）

1. **NG 没有任何一个实体能存「标题 + URL + 正文片段 + 图片」四元组。**
   正文在 `notes` / `page_texts`；图片只在 Easel（且是 dataURL 塞在设置 JSON 里）。
2. **`notes` + `note_folders` 就是 Edge 集锦的骨架**：文件夹树 ≡ 集锦列表、列表项 ≡ 卡片、
   备注编辑器 ≡ 富文本备注卡。**缺的只有两样**：① 卡片的 `kind`；② 抓取入口。
3. **`docs-new/4` 早已定过同一条纪律**（J5 阅读清单）：*"不新建 `domain-reading-list`，
   作为 notes 面板的一个视图"*。集锦应按**同一条纪律**处理 —— 否则就是第 9 个收集实体。

## 第三部分 · 三方案权衡（结论：融合，不新建）

### 方案 A · 新增独立「集锦」面板 + 新域 + 新表（照搬 Edge）

- 优点：概念一一对应，好讲。
- 代价：**第 9 个收集实体**；与 notes 的文件夹树/列表/编辑器 **90% 同构 → 两份实现必然漂移**；
  违反仓库红线（"不重复功能、死代码及时清除"）；且**微软自己都放弃了这条路**。
- **否决。**

### 方案 B · 删掉 Notes，只留集锦

- 代价：Notes 是**用户资产**（markdown / 标签 / 颜色球 / 置顶 / 稍后读 / 旧数据迁移适配器），
  删 = 数据迁移风险 + 功能倒退；"集锦"这名字对非 Edge 用户毫无先验。
- **否决。**

### 方案 C ·【选定】**融合：把 Edge 集锦内化为 Notes 的"卡片维度"**

**核心命题**：集锦 = "多类型卡片的文件夹"，而 Notes 已经是"文件夹 + 卡片 + 富文本"。
→ 给 Notes 补上 `kind`（卡片类型）与**抓取入口**，它就同时是笔记，也是集锦。

**为什么这是对的（不是折中，是正解）**：
- 模型级同构：Edge 集锦里**备注与网页卡片本来就是同一列表里的两类卡片**（§1.3-B/1.2）。
- 仓库级纪律：`docs-new/4`「不新建 domain-reading-list」的同一判断链。
- 产品级证据：微软的终局答案是"合并"，我们只是**合并得更完整**（连图片与备注一起保留）。

**取舍清单（明确"不做什么"，避免又一个半成品）**

| Edge 能力 | 我们的取舍 | 理由 |
| --- | --- | --- |
| 四种卡片（page/image/snippet/note） | **全做** | 这是集锦不可替代的内核 |
| 4 条录入路径（按钮/右键/拖放/浮动条） | **做按钮 + 右键**（P1）；**拖放**（P2）；浮动条**不做** | 跨 `WebContentsView` 拖放是最大不确定项；浮动条成本高、收益低 |
| 卡片拖拽排序 / 重命名 / 删除 / 打开 | **已有**（notes 现成） | 零成本 |
| 卡片多选 + 批量 | **做**（P3） | 中价值 |
| 编辑标题/描述 | **已有**（编辑器）+ 补"描述"字段 | 低成本 |
| **全部打开 / 复制全部** | **做**（P1） | 集锦级高频动作，成本极低 |
| 导出 Excel / Word / OneNote / Pinterest | **不做**，改**导出 Markdown / HTML** | 不引 Office 依赖；Markdown 是这个生态的通用语 |
| 跨设备云同步 | **不做** | NG 无账号体系；已有 profile 导出/导入 + 空间承载 |
| 购物 / 价格跟踪 / 返现 | **不做** | 已并入 Copilot，且与"收集"无关 |
| 移动端 | **不适用** | 桌面应用 |
| 回收站 | **顺带补**（notes 现在硬删除不可撤销） | Edge 的已知缺陷，别抄 |
| **增强（Edge 没有的）** | 标签 / 颜色 / 置顶（已有）+ **正文全文检索**（`page_texts`）+ **bangs 直达**（`!集锦`） | 这才是融合后的净收益 |

**与同族实体的边界（一次讲清，避免第二个"三足鼎立"）**

- **收藏 Favorites**：保持**纯 URL / 长期导航**。提供**单向搬运**（笔记 ⇄ 收藏 手动搬），**不自动同步**。
- **稍后读**：保持"Notes 的一个视图"（现状，`reading-list.mjs` 已是唯一真源）。
- **归档区**：保持**标签级**语义（收的是"标签"，不是"内容"）。
- **画板 Easel**：保持**自由画布**定位（卡片自由排布 + 笔迹）；与 Notes **共用同一份图片资产目录**（同文件两处引用，不重复落盘），并双向打通"卡片 → 画板"。
- **`page_texts`**：只服务"**按正文找**"（检索），不承担"收藏"职责（生命周期绑 URL 裁剪）。

## 第四部分 · 完整落地设计（照此施工）

### 4.1 数据模型（唯一改动点：给既有两张表扩列，**不新建表**）

真源：`1A-STAR_Hira_NG/infra/infra-db/src/schema.js`（`notes` / `note_folders`）

```
notes（扩列，全部带默认值 → 旧数据零影响）
  kind          text    default 'note'   -- note | page | image | snippet
  source_title  text    default ''       -- 来源页标题（卡片副标题）
  asset_path    text    default ''       -- 图片卡片：相对 userData 的落盘路径
  asset_mime    text    default ''
  asset_width   integer default 0
  asset_height  integer default 0
  thumb_path    text    default ''       -- 列表用缩略图
  ref_id        text    default ''       -- kind='ref'：被引用卡片的 id
  ref_mode      text    default 'chip'   -- chip（一行引用）| inline（把目标内容嵌进来）
  -- 复用既有列，不新增同义列：
  --   url        = 来源页 URL（page/image/snippet 都用它）
  --   title      = 卡片标题（page=网页标题；image=图片名/alt；note=笔记标题）
  --   content    = 正文（note=Markdown；snippet=选中原文；page=可选摘要/描述）
  --   folder_id  = 集锦（沿用文件夹树，含嵌套）
  --   tags / color / pinned / sort_order / created_at / modified_at 全部沿用
```

- **新增一张关系边表（"引用"的唯一真源）** —— 对 4.1 开头"不新建表"的**一处必要修正**，
  由"卡片之间要能互相引用 / 反链"这个新需求驱动：

```
note_refs(from_note_id, to_note_id, created_at)
  PK (from_note_id, to_note_id)；索引 (to_note_id)
  from = 引用方卡片；to = 被引用卡片
```

  - **为什么必须有它**：反链与"被引用 N 次"必须**可索引**。靠 `content LIKE '%[[…]]%'` 扫正文既慢又漏，
    而且"卡片引用"与"正文内联引用"会变成两套口径 → 必然漂移。
  - **卡片引用与正文内联引用写同一张边表** → 反链只有一份口径（这是"完美融合"的关键一针）。
  - 它**不是**第 9 个"收集实体"：它是**图上的边**，没有标题/正文/不能单独存在。
  - 边随卡片删除同步清理，由领域层在事务里保证（与 `note_folders` 现有做法一致）。

- 迁移：走既有 `migration/runner.js` + `adapters/notes.js` 同一范式（新增列 + 默认值 + 建边表）；
  `packages/shared-types/src/profile-archive.mjs` 里 `notes` 已登记，**无需改动**。
- 去重策略：**同一文件夹内、同 `kind=page` 且同 URL → 提升已有项而不是新增**；
  图片/片段**允许重复**（同一张图在不同语境有意义）。

### 4.2 领域层（`domain/domain-notes`，只加不拆）

- 新增**单一抓取入口** `addCaptured({ kind, url, title, sourceTitle, content, asset, folderId })`
  → 内部走既有 `add()`，统一处理 kind 默认值 / 资产登记 / `emitChange`（事件已现成）。
- `update()` 扩容字段白名单（kind 不可改；asset 只增删）。
- `remove()`：**顺带补回收站**（`deleted_at` 软删 + 恢复 + 定期清理）——
  一次把 Edge 的"删除不可撤销"缺陷也修掉。
- `removeFolder()` 现成的"子项回根、不级联删"语义保留。

### 4.3 图片资产（新增最小基础设施，两边共用）

- 目录：`userData/profiles/<profileId>/notes-assets/<assetId>.<ext>`（+ `thumbs/<assetId>.webp`）。
- 抓取：**主进程** `net.request` 拉图（带当前 session 的 cookie / referer）→ 原子落盘 → 记 `asset_path`。
  为什么不在渲染层 fetch：跨域必然失败；主进程侧与标签同 session 才拿得到图。
- 大图纪律：> 阈值（如 4MB）只留缩略图 + 原链；`easel` 迁移到**同一目录**（把 dataURL 落盘），
  一次回收掉设置里的大 JSON。
- 归档：`profile-archive` 二期把 `notes-assets/` 一起打包（先只搬记录，资产走"缺失则回源"降级）。

### 4.4 抓取入口（集锦的灵魂，4 条路里的 3 条）

| 入口 | 落点 | 分期 |
| --- | --- | --- |
| 面板「+ 添加当前页面」 | `panel-notes.view.js` 标题栏按钮 → `notesClient.addCaptured` | **P1** |
| 标签右键「添加到笔记…」 | 泛化既有 `tab-row-menu.js#onSaveToNotes`（现在写死"稍后读"）→ 弹出**文件夹选择器**（复用书签的"移动到…"子菜单范式） | **P1** |

- 搜索：现有客户端过滤**扩到 `source_title` / 内容**；二期接 `page_texts` 做"按正文找"。

### 4.6 命令 / bangs 接入（复用上一轮刚做好的 bangs 体系）

- 已有：`panel:<id>` 快捷 + "输入 `!` 列出全部" → 面板条目 `notes-panel`（标题"笔记"）**自动可搜**。

### 4.7 分期（每期都是**可独立交付**的完整功能）

- **P1 卡片骨架**：schema 扩列 + 迁移（含 `note_refs` 建表）+ `addCaptured` + 「+ 添加当前页面」+
  标签右键选文件夹 + 页面右键项 + **四态卡片渲染 + 两行版式 + 容器查询三档 + 密度 token 块**（一次做到位，
  不留"以后再说版式"）+ **集锦卡片墙根视图 + 空态主动作** + 全部打开/复制全部/导出 Markdown·HTML +
  **回收站（软删/恢复/定期清理）**（见 §7.4⑤：重磅功能的数据安全成本）。
- **P2 图片与文本**：资产目录 + 主进程拉图 + 图片/链接/文字右键项 + 拖放 + 缩略图。
- **P2.5 连接**：引用卡（chip/inline 两档）+ 边表读写 + 「复制引用/粘贴成引用」+ 编辑器 `@` 补全 +
  反链徽标与编辑器页脚 + 失效引用降级。
- **P3 打磨与互通**：多选批量 + 拖拽建引用 + 正文 `[[标题]]` 解析 + 密度设置档（舒适/紧凑）+

  读完"移动到集锦" + 标签批量收成集锦 + 会话 → 集锦。

### 4.8 风险与不确定项（先摆明）

1. **跨 `WebContentsView` 的 HTML5 拖放**是最大不确定项（Edge 的"拖图进面板"靠它）→ 先做右键路径，
   拖放放 P2；失败则降级为"右键 + 粘贴"。
2. **图片版权/尺寸**：只存缩略图 + 源链的降级路径必须有（大图不落盘）。
3. **迁移必须自动且无损**：新增列全带默认值，旧笔记 `kind='note'` 行为一字不变。
4. **不要顺手扩成"第二个书签"**：收藏与笔记的边界（导航 vs 项目）写进文档，避免重演 Edge 的结局。

## 第五部分 · 深度融合：引用 / 插入 / 反链（"连接起来"的具体做法）

> 用户问题：*"如何将集锦与 note 连接起来，有没有插入、引用等功能，能不能不要太割裂，而是完美融合？"*
> 这一部分回答"连接"，第六部分回答"排版"。

### 5.1 先把三个被混用的语义分清（否则一定会做成两种东西）

| 动作 | 语义 | 数据后果 | 界面表现 |
| --- | --- | --- | --- |
| **搬运 move** | 这张卡片改属另一个集锦 | 行还在，只换 `folder_id` | 拖到**文件夹**上（现状已实现） |
| **引用 reference** | 我指向那张卡片，**不复制内容** | 新增一条"边" | 一行 **chip**（图标 + 标题），点它跳过去 |
| **插入 insert / 嵌入 embed** | 把那张卡片的**内容**摊在这里 | 仍是同一条"边"，只是显示档不同 | 目标内容**内联展开**（只读）+ 顶部标注来源 |

关键设计：**"引用"与"插入"不是两种卡片，而是同一条边的两个显示档**（`ref_mode: chip | inline`）。
一张卡片右上角一个小图标即可在两档之间切换 —— 用户不会遇到"我到底该建引用还是插入"的选择题。

### 5.2 唯一真源：`note_refs` 边表

- 建立引用 = 往 `note_refs` upsert 一条边（`from → to`）；
- 卡片引用（`kind='ref'`）与正文内联引用**写同一张边表**；
- **反链** = `SELECT from_note_id FROM note_refs WHERE to_note_id = ?`（走索引，毫秒级）；
- **引用计数徽标** = 同一查询的 `COUNT`，直接画在列表行右侧（如 `↩3`）。

### 5.3 建立引用的三个入口（都要有，才不割裂）

1. **右键 →「复制引用」**（复制 `hira-note://<id>`）→ 在任意卡片编辑器里 **Ctrl+V** 时识别该 scheme
   → 就地生成 **引用卡**。与浏览器里"复制链接/粘贴"完全同构，学习成本为零。
2. **编辑器输入 `@`** → 弹补全（**当前集锦优先**，再全库，按最近修改排序，最多 8 条）
   → 选中后插入引用卡。这就是 Notion/飞书的 `@` 手感。
3. **拖拽**：把 A 卡片拖到 **B 卡片右侧出现的"引用落点"**（卡片 hover 时右侧浮出的小图标槽）
   → 生成引用卡。**拖到文件夹仍是移动**（5.1 的判据），两个手势语义清晰不打架。

另加一条**零成本**的：卡片右键 →「在此处插入引用」= 在当前集锦追加一张引用卡（不打开编辑器）。

### 5.4 反链怎么呈现（不另开页面，就长在卡片里）

- **列表行**：右侧徽标 `↩3`（被引用 3 次），点击展开为该卡片的**详情/展开态**。
- **编辑器页脚**：一行 `被引用 3 次 · 查看`（横向排列 3 个 chip，点即跳）。
- **引用卡的展示**：`chip` 档显示 `引用图标 + 目标标题 + 目标所在集锦名`；目标被删除时降级为
  `已失效的引用`（灰 + 可一键移除），**绝不静默消失**（否则用户会以为数据丢了）。

### 5.5 正文内联 `[[标题]]`（P3，可选糖）

- 保存时由**领域层**解析并 upsert 边表（解析只在写入那一刻做一次，读出永远是索引查询）。
- 解析规则：**同名唯一**才连；同名多条 → 不连（渲染为纯文本），并在编辑器里提示"有 3 个同名卡片"。
- 渲染：`hira-note://<id>` → chip 链接（点击 = 切到目标集锦并滚动高亮）。
- 明确取舍：**不做 `![[...]]` 的正文内联嵌入**（内联嵌入只用卡片档 `ref_mode='inline'`），
  避免"正文里有嵌入块"带来的编辑/保存复杂度。

### 5.6 明确不做（防止把简单功能做成 Notion）

- ❌ 双向同步编辑（嵌入块与源卡同时可编辑）——只读嵌入，永远只有一个写入点。
- ❌ 跨域引用（引用标签 / 书签 / 会话）——会让 notes 域反向依赖别的域，破坏四层解耦。
- ❌ 独立的"关系图谱"可视化页面 —— 与侧栏面板的定位不符。
- ❌ 自动反向链接全库扫描 —— 有边表就不需要。

### 5.7 「不割裂」的一线到底（验收清单）

融合是否成功，看这一张表就够了 —— 每行**只允许存在一处实现**：

| 维度 | 唯一实现（禁止出现第二套） |
| --- | --- |
| 内容实体 | `notes` 一张表（`kind` 区分卡片类型） |
| 分组 | `note_folders`（**UI 文案叫"集锦"**，代码里就是文件夹） |
| 连接 | `note_refs` 一张边表 |
| 列表渲染 | 一个 `renderCard(card)`（四态 + 两档引用） |
| 编辑器 | 一个编辑区（按 `kind` 决定显示哪些字段） |
| 搜索 | 一个搜索框（卡片 + 集锦 + 引用目标一次搜完） |
| 右键菜单 | 一个 `menu-client` 弹出器，按 `kind` 增删菜单项 |
| 拖拽 | 一套手势规则（拖文件夹=移动 / 拖卡片=引用） |
| 视图分段 | `NOTES_VIEWS` 一个枚举（`全部/稍后读/网页/图片/片段/引用`） |
| 入口 | 页面右键**只有一个**「添加到笔记…」（再选集锦/新建集锦） |
| 术语 | "集锦"只在**文案**层出现；代码与表里一律 `folder`（不造同义词） |

## 第六部分 · 侧栏面板的界面密度与排版（针对窄面板重做版式）

### 6.1 现状实测（`panel-notes.renderer.js` 的 injectStyles，真实数值）

| 元素 | 现值 |
| --- | --- |
| 搜索框 | 12px / padding 5px 9px / 圆角 7px |
| 视图分段 chip | 10.5px / padding 3px 7px |
| 文件夹行 | 12px / padding 5px 6px / 圆角 7px / 缩进 `8 + depth×14` |
| **卡片行** | 12px / padding 6px 8px / 圆角 8px / gap 8px |
| 颜色球 | 9px |
| 标签 chip | 10px / 圆角 999 / padding 0 5px |
| 日期 | 10px |
| 编辑器标题 / 正文 | 13px / 12.5px，line-height 1.65 |
| 预览 | 12.5px / line-height 1.7，h1 17 / h2 15 / h3 13.5 |

**结论：字号其实已经够小，问题不在"太大"，而在"一行塞了太多东西" + "没有宽度自适应"。**
面板宽度可在 200–600px 之间拖（默认约 300px），在 300px 宽里把
`颜色球 + 标题 + N 个标签 + 日期` 全挤在一行，结果必然是三者互相抢空间、各自被截断成省略号。

### 6.2 目标版式：**两行卡片** + **容器查询三档**

```
┌──────────────────────────────────────────┐
│ ● [kind图标/favicon/缩略图]  标题（1 行省略）   │  13px / 600 / 1.35
│   来源域名 · 8月3日   [标签] [标签] [+2]        │  10.5px / 次色
└──────────────────────────────────────────┘
     padding 6px 8px  圆角 8px  行间距 4px
```

- **第一行只放"身份"**：态图标 + 标题。标题恒为**1 行省略**（不再是多行卡片）。
- **第二行只放"归属"**：来源域名（网页/片段/图片卡才显示）· 日期 · 最多 **2 个**标签 + `+N`。
- 颜色球移到**左侧色条**（2px 宽、贴合卡片左缘）而不是占一个 9px 圆点 ——
  纵向列表里"色条"比"色点"更省宽度也更好扫（可与 ui-common 跟随 favicon 取色的做法共用视觉语言）。
- 图片卡：`56×56` 缩略图左置（圆角 6px），右侧两行；行高自然撑到 68px。

**容器查询（`container-type: inline-size`）三档** —— 用容器查询而不是媒体查询：
面板宽度与窗口宽度无关，`@media` 在这里从根上量不准。

| 档 | 触发 | 变化 |
| --- | --- | --- |
| 紧凑 | `< 280px` | 第二行只留日期；域名与标签全部隐藏（悬停 title 提示）；缩略图降到 44×44 |
| 标准 | `280–420px` | 6.2 的默认版式 |
| 宽松 | `> 420px` | 第二行追加**摘要 1 行**（`excerpt`/正文首行）；标签最多 4 个；缩略图 64×64 |

### 6.3 密度收口：一个 token 块，两档切换

把上表所有数值抽成 `.notes-panel` 上的局部变量（**唯一真源**，别散在各规则里）：

```css
.notes-panel {
  --notes-fs-title: 13px;    --notes-fs-meta: 10.5px;
  --notes-row-pad: 6px 8px;  --notes-row-gap: 4px;   --notes-radius: 8px;
  --notes-thumb: 56px;       --notes-indent: 14px;   --notes-hit: 28px;
}
.notes-panel[data-density="compact"] {          /* P3：设置项 notes.density */
  --notes-fs-title: 12.5px;  --notes-fs-meta: 10px;
  --notes-row-pad: 4px 6px;  --notes-row-gap: 2px;   --notes-thumb: 44px;
}
```

- 触控/点击目标下限 `--notes-hit: 28px`（行高、图标按钮、chip 一律不小于它）——
  窄面板里最容易犯的错就是把可点区域压到 20px 以下。
- 缩进用 `--notes-indent`（14px），**不用 8+14×depth 的硬算**（深度 5 层时 78px 会吃掉 1/4 面板宽）；
  超过 3 层改为"面包屑 + 只显示当前层"（现状的 `openFolder` 机制已经支持，只是不再无限缩进）。

### 6.4 编辑器排版（窄面板里"读得下去"比"信息多"重要）

- 正文**行长上限** `max-width: 46em`（≈ 34 个中文字），面板拉宽时不把一行拉成 600px 长句；
- 字号 12.5→**13px**、`line-height: 1.6`，段间距 `0.6em`（现在是 1.65 略松，窄面板里显得"碎"）；
- 预览里的标题间距 `margin: 0.6em 0 0.3em` 收紧到 `0.5em 0 0.25em`；
- 代码块 padding 8px 10px → `6px 8px`、字号 11.5px 保持（代码本来就该小）。

### 6.5 与"融合"的联动（排版不是独立话题）

- 卡片有 `kind` 之后，**图标位必须统一**：`page`=favicon、`snippet`=引号图标、`image`=缩略图、
  `note`=便签图标、`ref`=箭头图标。这一个图标位就让"四种卡片"在同一列里**看起来是一家人**。
- 引用卡与嵌入块共用第二行的"来源"位（引用卡第二行写"→ 目标所在集锦"），
  于是"引用"在列表里的视觉重量与一张普通卡片一致 —— **这就是"不割裂"的视觉层面的全部秘密**。

| 18 | 排序（modified/created/title） | `NOTE_SORTS` + `#setSort` | 保留 | 原样 |
| 19 | 旧数据迁移（`notes.json` + `localStorage['hira-notes']`） | migration adapter + `#importLegacyOnce` | 保留；新增列全带默认值 → **旧数据行为一字不变** | 原样（必须） |
| 20 | IPC 17 条 + `note:changed` 广播 | `ipc/notes.js` + `contracts/notes.js` | 保留；新增 `capture` / `refs` / `backlinks` / 回收站若干条 | 增强 |
| 21 | profile 导出/导入含 notes | `profile-archive.mjs` | 保留 + `note_refs` 进清单 | 增强 |
| 22 | 面板宽度 / 侧别持久化 | `app.panel_width_left/right` | 保留 | 原样 |

> **结论：零功能损失。** 22 项里 12 项原样、10 项增强，**没有任何一项被集锦挤掉**。
> 唯一"改动语义"的是第 4 项（硬删 → 软删），方向是**更强**，不是更强硬。

### 7.2 稍后读：**必须保留为独立泳道，不许被集锦吸收**

稍后读与集锦最容易互相排挤，规则一次定死：

| | 稍后读 | 集锦 |
| --- | --- | --- |
| 语义 | **待读队列**（"我还没来得及看"） | **主题板**（"我在做这件事"） |
| 形状 | 单层、URL 为主、**幂等去重** | 多层、四种卡片 |
| 入口 | 标签右键**一步直达**（不弹选择器） | 「添加到笔记…」→ 弹选择器（可新建集锦） |
| 视图 | 独立分段（现状 `reading`） | 独立分段（`集锦`/`全部`） |
| 排序 | 按加入时间/未读优先 | 按用户拖拽顺序 |

**不排挤的三条硬规则**：
1. **两条入口并存，互不替代**：`加入稍后读` 与 `添加到集锦…` 在标签右键里**同时存在**且并列。
2. **同一实体、不同落点**：两者都是 `kind='page'` 卡片，只是默认 `folder_id` 不同 → 数据层零分叉。
3. **稍后读是"隐式集锦"，不可删除/重命名**（现状已是特殊文件夹）；用户不能把它拖走，
   但可以"读完后归档到某个集锦"（P3：读完 → 移动到集锦）。

### 7.3 同族功能互不排挤（泳道规则表）

| 同族 | 定位（一句话） | 与集锦的关系规则 | 冲突时的裁断 |
| --- | --- | --- | --- |
| 收藏 bookmarks | 长期**导航** | 互不自动同步；提供手动**双向搬运** | 集锦不写 `bookmarks` 表；搬运是显式动作 |
| 归档 archive | 标签级**自动**回收站 | 不合并；提供"归档项 → 加入集锦"（复制成 page 卡） | 归档仍是标签语义，永不装内容 |
| 画板 Easel | **自由画布** + 笔迹 | **共用同一份图片资产目录**；双向"卡片 → 画板" | 收藏用列表、编排用画布，各司其职 |
| `page_texts` | **检索索引**（绑 URL 生命周期） | 集锦只**读**它当摘要来源，永不写 | 它被裁剪时集锦卡片不受影响（卡片自带字段） |
| 打开的标签页 | 运行时列表 | 新增「把选中的标签收成一个新集锦」 | 单向：标签 → 集锦 |
| 命名会话 | 一次性恢复 | 提供"把会话存成集锦"（P3） | 单向 |
| 搜索/地址栏 | 全局入口 | `!集锦` / `!collections` / `!save` 直达（复用 bangs） | 集锦不新造全局搜索 |

### 7.4 把集锦当"重磅功能"来对待（分量设计）

**重磅 ≠ 加面板，而是六件事一起到位：**

1. **信息架构升级（不是加一个视图）**
   - 面板根视图 = **集锦卡片墙**（名称 + 卡片数 + 封面拼贴 + 更新时间），点进即卡片板；
   - `全部` 分段保留平铺卡片（兼容"用户根本不建集锦、只在根级堆卡片"的现状）；
   - 类型过滤收进"筛选"按钮，不在窄面板里铺 6 个分段 chip。
2. **入口的分量**：页面右键 + 标签右键 + 面板内「+ 添加当前页面」+ 地址栏 `!集锦`/`!collections`
   + 一个可选的导航栏按钮（走既有可编辑按钮体系 `app.navbar_buttons`，不硬编码）。
3. **能力的分量**（整集锦级动作）：全部打开（新窗口成组标签）/ 复制全部 /
   导出 Markdown·HTML / **存为会话**（融合价值）/ 重命名 / 删除（可恢复）。
4. **性能的分量**：卡片墙与列表**只画可见项**（沿用现有行增量 diff 的思路，不做全量重排）；
   缩略图懒加载；只存缩略图不存原图（大图回源）。
5. **数据安全的分量**（这是"重磅"的成本，必须有）：
   - **回收站（软删）从 P3 提到 P1** —— 用户敢往里放重要资料的前提；
   - 导出（Markdown/HTML）P1 就要有；
   - `profile-archive` 覆盖 `notes` / `note_folders` / `note_refs`（+ 资产目录二期）。
6. **可发现性的分量**：空面板的主动作是「新建集锦」+「把当前页面收进来」；
   首次使用不出现"空白列表 + 一排图标"。

### 7.5 分期调整（因"重磅"而上移的两项）

- **上移到 P1**：回收站（软删 + 恢复 + 定期清理）、导出 Markdown/HTML、
  集锦卡片墙根视图、空态主动作。
- **不变**：P2 图片与文本 / P2.5 连接 / P3 打磨与互通。
- **P3 新增**：读完后"移动到集锦"、标签批量收成集锦、会话 → 集锦。

### 7.6 一句话回答"如何不排挤"

> **把集锦做成"文件夹 + 卡片类型 + 边"的三层能力，而不是第四个实体；**
> 稍后读保留独立泳道（两条入口并列、同一实体不同落点）；
> 收藏/归档/画板/正文索引各自守着"导航 / 标签 / 编排 / 检索"的边界，
> 只做**显式单向搬运**、绝不自动同步 —— 这样谁都不会被谁吃掉。

## 第八部分 · 「完全体」复刻标准（唯一参照：Edge ≤144 的经典集锦）

> 用户定调：**参照物是 145 之前的黄金期完整集锦**——它口碑极好、支持率极高，只是被微软砍了。
> 因此**不得以"微软已经删了 / 已经并进收藏夹"为理由做功能裁剪**；
> 第二部分那些"微软的迁移代价"只当**反面教材**（别学它丢内容），不当缩水借口。

### 8.1 档位定义（后面所有功能都按这个标）

| 档 | 含义 |
| --- | --- |
| ✅ **完全一致** | 同语义同手感，可 1:1 复刻 |
| 🔁 **等价实现** | 换技术手段，用户拿到的结果等价 |
| ⬇️ **降级** | 能力保留但弱化（必须写清降级点与替代路径） |
| ➖ **不适用** | 平台/账号原因无对应场景（必须给替代手段） |

## 结论（一句话）

**不新建"集锦"实体**：把 **Edge ≤144 完全体**集锦的 **四种卡片（page/image/snippet/note）+
6 条录入路径 + 卡片全部操作 + 集锦级动作 + Office 导出 + Ctrl+Shift+Y** 全量融进既有 **Notes**
（它已经是"文件夹 + 卡片 + 富文本"）；图片资产落盘共用一份；Office 三件套以**生成
`.xlsx` / `.docx` / HTML 文件**等价实现；只有"账号云同步 / 移动端 / 购物"三类因平台原因不适用（各给替代），
并把经典的"删了不能撤销"升级为回收站。收藏只做 URL 导航、不与之争地盘。
净结果：**功能不减于经典完全体（还多出标签/颜色/置顶/引用反链/全文检索/bangs 直达），实体数不增，**
与仓库"不重复功能、死代码及时清除、唯一真源"的红线一致。
