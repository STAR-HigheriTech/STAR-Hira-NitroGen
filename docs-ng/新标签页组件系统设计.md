# 新标签页 · 小组件系统与新闻源设计

> 范围：`hira://newtab` 这一张页面。**不涉及主进程、不涉及 IPC 契约、不涉及插件系统** ——
> 页面的摆放与配置全部落在自己的 localStorage 里，浏览器内核一行都不用动。

---

## 1. 目标与边界

| 要做的 | 不做的 |
| --- | --- |
| 三种内置组件：时间 / 日期 / 新闻热点 | 不新增主进程 IPC 路由 / domain 包 / 正式插件机制 |
| 拖拽摆放 + 改尺寸 + 增删 + 每组件设置 | 不改 `hira-protocol.js`（静态页自动注册已经够用） |
| 摆放**按断点分桶**持久化（用户资产） | 不改 `electron.vite.config.js`（`pages/` 本来就整棵拷贝） |
| 新闻源做成注册表，可无限加 | 不引入打包器 / 框架（内部页是"原样拷贝的 ESM"） |

### 为什么是纯 ESM 而不是 TS

`pages/` 下的文件由 `copyMainSourcesPlugin` **原样拷贝**到 `out/pages/`，页面上直接
`<script type="module">`。那份插件对 `.ts` 是按 **CJS** 转译的（给 main 进程用），
转出来的东西浏览器加载不了。所以内部页只能用 ESM + JSDoc 类型 —— 这是既有约定
（见 `pages/README.md`），不是偷懒。

## 3. 组件契约

一个组件就是一份声明 + 一个 `create(ctx)`：

```js
defineWidget({
  id: 'clock',
  name: '时间',
  unique: true,                              // 全局只允许一个
  // 常驻型组件（搜索框）才用下面三条，普通组件不用写：
  hidden: false,                             // true = 不进「添加组件」
  removable: true,                           // false = 不给 ✕
  shape: '',                                 // '' 圆角矩形 | 'capsule' 胶囊
  defaultSize: { w: 7, h: 3 },               // 按主断点 16 列声明
  minSize: { w: 4, h: 2 },
  maxSize: { w: 11, h: 5 },
  settings: [
    { key: 'hour12', label: '12 小时制', type: 'boolean', default: false },
    { key: 'source', label: '内容源', type: 'select', default: () => defaultProviderId() }
  ],
  create(ctx) {
    // ctx.root / ctx.config / ctx.setConfig / ctx.size / ctx.isEditing / ctx.openUrl
    return { destroy() {}, resize(size) {} }   // 两个钩子都可选
  }
})
```

- `settings` 的类型支持 `boolean | select | range | number | text`；
  `options` 与 `default` 都可以是**函数**（`default` 是函数是为了让默认值能依赖
  "注册中心里现在有什么"，从而与 `import` 顺序无关）。`unit` 是可选显示后缀（如 `%`）。
- **每个组件自动带通用外观设置**：`底色不透明度`、`背景模糊`、`字体颜色`。
  组件**不要**自己声明它们（`defineWidget` 会直接报错拦住）。
  它们归板层：底色与字体是**卡片**的属性，不是组件内容的属性 ——
  `defs/*` 只画自己那块内容，卡片是板层画的。所以只声明一次
  （`widgets/appearance.js`），注入一次（`defineWidget`），落地一次
  （`board#mountContent` → `applyAppearance`），**组件一个字都不用改、也不知道有这回事**。
  落地方式是**改 CSS 变量**而不是写死样式：不透明度写 `--wgt-bg-alpha`、
  模糊写 `--wgt-blur`、字体写 `data-fg`（在卡片上重写 `--ntp-text` / `--ntp-text-soft`），
  于是"调透明度"不需要为每种模式、每个组件各写一条规则。
- **"每个组件都一样"是默认，不是铁律 —— 组件可声明 `appearance` 改档**：

  ```js
  // 时间 / 日期：大字浮在壁纸上，不需要底座
  appearance: { bgOpacity: { min: 0, max: 100, default: 0, staleDefault: 100 } }
  ```

  | | 范围 | 默认 | 为什么 |
  | --- | --- | --- | --- |
  | 普通卡片（新闻 / 搜索…） | **35% – 100%** | 100% | 装的是正文，底色透到 35% 以下就读不清了 |
  | 时间 / 日期 | **0% – 100%** | **0%** | 一串大字浮在壁纸上，不需要底座；想铺实底也能调到 100% |

  只能改范围 / 默认值 / 标签，或 `omit: ['bgBlur']` 整项去掉，**不能新增字段** ——
  字段清单只有 `appearance.js` 一处真源，所以"多一个通用外观"仍是改那一个文件，
  而不是满项目找哪里又加了一条规则。

  两个配套机制，都是为了让"档"真的生效：

  - **夹取按组件自己的档**（`appearanceOf(def)`）：设置面板拉得到多少、实际就生效多少，
    老数据超出新范围会被自动收进来 —— 不会"显示 35、实际按 100 画"。
  - **`staleDefault` 让改默认值能追到老数据**：configs 在实例创建时就把 schema 的全部默认值
    落库了，"从没动过"与"就是设成了这个值"在数据上无法区分。声明旧默认值后，
    存着它的实例被当作从没动过、直接吃新默认值；用户手动设过的其它值分毫不动。
    没有这一条，改默认值只对新实例生效，既有卡片纹丝不动（观感：改了没反应）。
- **大字组件的可读性投影**：时间 / 日期默认没有底色，一串大字直接压在壁纸上会糊 ——
  所以它们吃一个投影。"用哪个影子"由**一个变量**决定（`--ntp-text-shadow`），
  三处写、一处用：
  | 场景 | 取值 | 为什么 |
  | --- | --- | --- |
  | 跟随主题 · 浅色 | `--ntp-fg-dark-shadow`（浅影） | 浅色主题字色是黑的 |
  | 跟随主题 · 深色 | `--ntp-fg-light-shadow`（深影） | 深色主题字色是白的 |
  | 显式选白 / 黑字 | 由 `.wgt[data-fg='…']` 覆盖上面两档 | 影子跟的是**字色**，不是主题 |

  于是"跟随主题"**不是没有影子**，而是按主题实际呈现的黑 / 白自动选一个
  （主题落在 `html[data-theme]` 上，见 `_shared/runtime.js#initTheme`）。
  §5 只写一句 `.wg-clock, .wg-date { text-shadow: var(--ntp-text-shadow) }` ——
  那里**不做任何颜色判断**，只回答"谁要影子"；`text-shadow` 是继承属性，
  挂在组件根节点上就覆盖了它全部文字。以后再有"大字组件"把类名补进这个选择器即可。
- **`hidden` / `removable` / `shape` 是给"常驻型组件"用的三条声明**（目前只有搜索框）。
  板层只读声明、不认识任何 id，所以"搜索框长成胶囊、删不掉、不进选择器"这三件事
  都不需要在板层里写 `if (id === 'search')`。
- `ctx.size` / `resize(size)` 同时给**网格尺寸**（`w/h`）与**像素尺寸**（`pxW/pxH`）。
  组件的自适应判断请一律用**像素**那两个 —— 网格粗细（列数 / 行高）是会变的，
  用格数当阈值会在每次调网格时失效。
- 改配置 = 板层把该实例整块重挂（`mountContent`）。组件不必写增量更新逻辑。
- 尺寸自适应走 **CSS 容器查询**（`.wgt__body` 是 `container-type: size`），
  组件内部用 `cqw/cqh` 排版，于是同一组件被拉成任意宽高都刚好合适，
  不需要 JS 算字号。

## 4. 摆放：网格、碰撞、断点

### 4.1 网格

- 断点两档：`wide`（≥900px，**16 列**）/ `narrow`（<900px，**8 列**）。
- **行高 52px，间距 12px** ⇒ 步长 64px（横竖一致）；**坐标一律是网格单位**，像素换算只在渲染那一刻发生。
- 位置一律写 `transform: translate3d()`（不是 `left/top`）→ 拖拽全程只走合成层。

> **网格为什么收细**：网格粗细 = "一次拖/一次缩放跳多远"，也就是手感粗细。
> 初版是 12 列 / 行高 84 / 间距 14（步长 86×98px），反馈是"缩放太大、没法自己调到合适" ——
> 步长大就等于每次都是大跳。收细到 16 列 / 52 / 12（步长 64px）后才有"微调"的余地。
>
> 收细网格意味着**列数与行步长都变了**，所以存储里存下来的 `x/w`（按列）与 `y/h`（按行步长）
> 必须等比换算，否则老布局会缩在左上角、每张卡还矮一截。这就是 `store.js#migrateV1toV2`
> 存在的原因（数据版本 1 → 2）—— **摆放是用户亲手摆的资产，不能因为一次"把格子调细"报废**。

### 4.1.1 搜索框也是网格里的一项

搜索框从"页面里写死的一行"变成了**常驻组件**（`defs/search.js`，`hidden + removable:false + shape:'capsule'`）。
于是它天然获得"可拖动 / 可缩放"，别的组件也就能摆到它**上方** ——
不需要为"搜索框上方"单独开一条布局通道。板层仍然不认识 `search` 这个 id，全部靠声明行事。

老数据（v1）里没有这一项，`board#ensureSearch()` 会补一个：落在顶部正中，
若正中已被占就**就近**找空位 —— 只动搜索框自己，绝不把已有组件推开。

### 4.2 拖拽为什么不卡

两个关键取舍：

1. **跟手与落点分离**：被拖的那一格按**真实像素**走（1:1 跟手，不吸附），
   落点每帧只算给自己；松手才提交。**别的格子全程纹丝不动。**
2. **每帧只写、不读**：rAF 回调里只对已知元素赋 `style`，不做任何
   `getBoundingClientRect` / `offsetWidth` 之类的布局读取，因此不产生强制回流。

拖拽/改尺寸期间 `.wgt.is-dragging` 关掉 transition（否则跟不上手），
松手后恢复 transition，由它把卡片稳稳收进格子（0.19s）。

### 4.3 落位：只影响被操作的那一格（`placeFree`）

```
placeFree(rects, size, cols, want, excludeId)
```

**唯一**的「用户操作」落位入口（拖拽 / 缩放 / 新增；整档推导另有 `placeDown`，见 4.4），语义只有两句：

- `want` 不压到别人 → 原地就用；
- 压到别人 → 从 `want` 出发**由近及远**找第一处空位，**只挪这一格**。

看板向下生长不设上限 ⇒ 一定能找到，绝不返回 null，更不会去推别人。

> **为什么删掉了重力压缩（`compact`）与重叠让位（`resolve`）**：
> 曾经的规则是"拖动一格时其它格子实时让位 + 最后整体上浮补洞"。
> 用户的原话是"随意惯性改原本好好的位置"—— 拖搜索框，别的卡吸附上来；
> 拖别的卡，搜索框自己跑走。摆放是用户亲手摆的资产，**系统无权在他拖 A 时挪 B**。
> 于是整条"上浮 / 让位"机制被删除，`grid.js` 只剩 `placeFree`：
> **洞就是洞**，用户想补自然会去拖。

改尺寸同一条纪律：长进别人的地盘就**停在当前尺寸**（卡住），不推别人。

### 4.4 断点分桶

`state.layouts` 是 `{ wide: {i: rect}, narrow: {i: rect} }`。

理由：拖拽是用户亲手摆的资产。在窄窗口里拖动，**不该**偷偷改写宽窗口里的摆放。
两档各自记住自己的布局，缺的那一档按另一档按比例推导（`ensureLayout`）——
推导是确定性的，同一个源布局永远得到同一个结果。

推导必须守住「视觉顺序 + 三对称锚点」，否则窗口一窄就会塌成一列：

- 按源布局的**视觉顺序**（先 `y` 后 `x`）逐个推导，并保证后推导卡片的顶边不高于先推导卡片
  （`floorY`）—— 谁在上、谁在下原样带过来；
- 落位走 `grid.placeDown`：横向仍只认贴左 / 正中 / 贴右三处锚点（按**新宽度**重算，
  所以贴右的仍贴右、居中的仍居中），纵向**只向下**压。
  不能用 `placeFree`（它会向上找空位），否则后推导的小卡片会钻进前面的空隙，顺序就乱了；
- 已有位置只做收敛；吸附后若压到别人就保持原样 —— 宁可不对齐，也绝不制造重叠。

> v2 → v3 迁移会丢弃非主断点的布局桶（v2 推导出的窄屏布局已经坏掉且无法分辨来源），
> 交给新算法重新推导；主断点是用户亲手摆的，原样保留。

`ResizeObserver` 只对**宽度变化**作反应（我们自己会写 `minHeight`，
不过滤就会自激循环）。

### 4.5 持久化

一份带版本号的 JSON，键 `hira.ntp.board.v1`：

```js
{ version: 1, seeded: false,
  instances: [{ i, widget }],                   // 身份
  configs:   { [i]: {...} },                    // 配置（与位置无关，改配置不动布局）
  layouts:   { wide: { [i]: {x,y,w,h} }, narrow: {…} } }
```

- 拖拽中高频调用 `save()`：合并写入，120ms 内只落一次盘（跟手与落盘彻底解耦）。
- 页面 `pagehide` / `beforeunload` 时 `flush()`，最后一次拖拽不会丢。
- `normalize()` 对脏数据**永不抛错**：拿不准的整条丢弃，宁可回到空看板也不能让页面白屏。
- `seeded` 标记"首次默认摆放已经放过"。用户把组件全删光也是他的选择，
  下次不会再给他摆回去（与 `app.speed_dial` 同一口径）。

### 4.5.1 默认预设的**修订表**（重做默认构图时怎么升级老用户）

默认摆放不再是"一份写死的清单"，而是 `sections/home.js` 里一张**按修订号排列**的 `PRESETS`：

- 板层（`board.js`）仍然**不认识任何组件 id**，整张表由调用方传进来；
  生效的是**最后一版**，前面的版本只用于识别"老用户还停在当年那套没动过的默认"。
- **每重做一次默认构图：往表尾追加一版，不改历史版本。** 删掉旧版，
  那些老用户就永远识别不出来了。
- 启动顺序：`seedDefaults()`（仅首次） → `upgradePreset()` → `ensureSearch()` → `ensureLayout()`。
  `upgradePreset` 逐格比对**所有旧版**预设（实例集合完全对应、主断点每一格都相等），
  命中才把当前版套上去：**保留实例 id 与全部配置**，只改位置；非主断点清空交给
  `ensureLayout` 重新推导。用户亲手摆过的布局一个字都不动。
- 该机制**幂等**（换完即匹配当前版，下次不再触发），所以存储里不需要 `preset` 字段、
  也不用 bump `VERSION` —— 迁移的判据就是布局本身。

**修订 2（收紧版）**：旧默认占 13 行（约 820px，900p 屏首屏要滚动），且新闻 / 快速拨号都是
16 列满宽，观感"每张卡都过大"。新版整块 8 行（500px），一屏放下：

```
search  8×1  @x=4  （居中，约半屏宽）
clock   7×2  @x=0
date    7×2  @x=9  （与时间卡左右对称，中间留 2 列）
news    8×4  @x=0
speed-dial 8×4 @x=8
```

各组件 `defaultSize` 同步瘦身（于是「添加组件」新加进来的卡也不会再是一整屏宽），
紧凑态阈值按**像素**重定：时钟 `pxH<100`、新闻 `pxH<230` —— 阈值必须低于新默认高度，
否则默认卡一落地就被判成紧凑态。

---

### 4.6 铁律：编辑模式**不得改变布局**

进 / 出编辑模式时，所有组件（含搜索框）的位置必须**一动不动**。
否则"编辑时看到的位置"就不是"实际位置"，拖动会变成一件说不清的事。

做法就两条，都很朴素：

1. **看板高度在两个模式下由同一条规则算出** —— `rows = maxRow`，不按编辑态加行。
2. **看板在 CSS 里就是 `flex: 1`**，铺满可用区；内联 `min-height` 只是"组件排到画布之外"时的下限。

### 4.7 网格是一块**固定铺满的画布**

不是"内容多高就多高"的盒子，内容也**从画布顶部开始排**（不做垂直居中）——
一旦居中，组件少的时候上方会空一大片。

这条踩过两次，都留个记录：

| 踩的坑 | 后果 | 正确做法 |
| --- | --- | --- |
| 进编辑模式把**看板本身**撑高到视口高度（当时为了让网格铺满） | 看板在 flex 里垂直居中 → 变高后被重新居中 → **整块内容上移一百多像素**：编辑时看到的位置 ≠ 实际位置 | 看板本来就该 `flex: 1` 铺满可用区、且**不做垂直居中**。网格自然铺满，两个模式高度也天然一致，连"多铺多少"都不用量 |
| "编辑模式至少留 4 行"这条下限 | 内容少时仍是残余位移 | 删掉。网格可见性由"铺满的画布"负责，不需要动布局 |

连带收益：上一版为"网格多铺出去"写的 `--ntp-grid-fill` 与 `board.js#measureFill()`
（含那次测量与窗口 resize 监听）**整条删掉了** —— 画布本身就铺满，不需要额外测量。

**教训**：为了让装饰（网格点）多铺一点而去动**布局盒**，是拿真实布局换观感。
装饰该长在装饰层上（伪元素、绝对定位），不该长在布局上。

### 4.8 历史记录：压缩曾经把"正在拖的那一格"推回顶部

> 本节是**已删除机制的复盘**，保留下来当教训 —— 现行代码里已没有 `compact` / `resolve`。

`grid#compact()`（重力压缩，"上面有洞就补上"）当年必须**跳过得传进来的 `pinnedId`**，
并且**先让它占位**（其他人上浮时才不会飘到它头上）。

漏过这一条，症状很典型：**单个搜索框往下拖进空白网格，手一松就弹回顶部** ——
因为压缩看到"它上面没东西挡着"，就一路把它推回 `y = 0`。

**教训**：`pinnedId` 这种"让算法别动某格"的补丁，本质是算法本身就不该动别人。
后来用户把问题说透了 —— 不止是"别动正在拖的那格"，而是"**别动任何一格**"。
于是补丁连同整套压缩一起删掉，换成 `placeFree`（见 §4.3）。

## 5. 新闻源规划

### 5.1 新闻从哪来

新标签页是 `hira://` 页面，`webSecurity` 是开的，所以**只能用带 CORS 头的公开接口**，
不能走自定义请求头、不能带鉴权。

**2026-10-07 实测重排了一次。** 初版选了 5 家免鉴权来源 + 1 个离线兜底，
实际跑下来只有 2 家能出内容：两个第三方热榜聚合站
（`api-hot.imsyy.top` / `api.vvhan.com`）**域名已经解析不到**了 ——
不是限流、不是地区问题，是服务没了。于是四个源（知乎/微博/百度/36氪）连同
它们共用的 `providers/hotlist.js` 一起删掉。

现在**只接第一方接口**（服务方自己的官方 API）：

| 顺序 | id | 名称 | 接口 | 语言 | 实测 |
| --- | --- | --- | --- | --- | --- |
| 1 | `sspai` | 少数派 | `sspai.com/api/v1/article/index/page/get` | 中文 | 200 · ACAO `*` |
| 2 | `hackernews` | Hacker News | `hn.algolia.com/api/v1/search?tags=front_page` | 英文 | 200 · ACAO `*` |
| 3 | `devto` | dev.to | `dev.to/api/articles?top=7` | 英文 | 200 · ACAO `*` |
| 4 | `curated` | 精选 | 本地常量 | 中文 | **不联网、不会失败** |

**这次重排得出的结论（比源本身重要）：**

- **第三方热榜聚合站是会被关掉的，第一方不会。** 聚合站边际成本高、没有主业支撑，
  关停只是时间问题；而被选中的这三个都是服务方自己在跑的接口。所以"多接几家聚合"
  换来的不是冗余，是**同一时间集体失效**。
- 只测 DNS / HTTP 200 不够，还要看 **`Access-Control-Allow-Origin`**：
  B 站的热门接口 200 但 ACAO 为空，在页面里照样被 CORS 挡掉。
- 顺手验证失败的还有：v2ex（超时）、Reddit（超时）、掘金（路由已变）。

其余设计要点（未变）：

- **一次请求拿完**：HN 用 Algolia 而不是官方 Firebase API —— 后者要 1+N 次请求
  （先取 id 列表再逐个取详情）。新标签页是常开的页面，请求数是真成本。
- **`curated` 必须注册在最后**（`buildChain` 按注册顺序排队）。它是唯一保证成功的一环，
  于是断网 / 被限流 / 接口挂了，新闻卡也永远有内容，而不是一张"加载失败"的空白卡。
- **不硬凑 `hot`**：少数派的点赞量级是个位数，显示成「热度 5」没有意义，
  那个源就不给 `hot`（卡片只显示「来源 · 时间」）。少一项信息好过给一项噪音。

### 5.2 降级链

`service.loadNews()` 按顺序尝试，先命中先返回：

```
① 目标源的新鲜缓存（< 15 分钟）   ← 0 请求，切回新标签页立刻有内容
② 目标源真实请求（7s 超时）
③ 其余源依次尝试
④ 任意源的过期缓存（stale，UI 上标"离线缓存"）
⑤ curated（一定成功）
```

- 每个源按 id 分开缓存（`hira.ntp.news.v1.<id>`，最多 40 条，TTL 15 分钟）。
- 单源失败静默跳过，不影响整条链。
- 归一化时丢掉没有标题/链接的脏项、按 URL 去重、只放行 `http(s)`。

### 5.3 换源的成本

换一个取数策略（比如改成主进程代理、加 RSS、接自己的后端）只需要：

1. 新增 `news/providers/<name>.js`，内部 `defineProvider({ id, name, fetch })`；
2. 在 `newtab.js` 的新闻源清单里加一行 import。

`defs/news.js`（组件）、`service.js`（缓存与降级）、设置表单的"内容源"下拉
**都自动跟上** —— 下拉选项就是 `listProviders()`。

---

## 6. 怎样再加一个组件

1. 新增 `widgets/defs/<name>.js`，内部 `defineWidget({...})`（模块被 import 即注册）；
2. 在 `newtab.js` 的组件清单里加一行 `import './widgets/defs/<name>.js'`；
3. 样式写进 `newtab.css` 的 `wg-<name>__*` 段（类名带组件前缀，不会串味）。

不需要动 `board` / `registry` / `picker` / 设置表单 —— 它们只认注册中心。

## 7. 已知取舍

| 取舍 | 原因 |
| --- | --- |
| 不做农历 | 农历要一张随年份更新的历表，塞进新标签页不划算 |
| 断点两档而不是任意列数 | 两档已经覆盖真实窗口宽度；任意列数会让"每档存一份布局"的存储无界 |
| 新闻接口依赖第三方公开服务 | 内部页拿不到主进程网络能力（守"不改主进程"的边界）；崩溃时 `curated` 兜底 |
| 组件改配置即整块重挂 | 组件不必写增量更新逻辑；重建成本远低于耦合成本 |

# 第二部分 · 按 Vivaldi「层系统」重构

## 8. 边界（这个重构改什么、不改什么）

| | |
| --- | --- |
| **改** | `apps/app-main/src/pages/newtab/**` 的全部文件（HTML / CSS / JS） |
| **不改** | 载体（仍是 `hira://newtab` 静态内部页、仍在 tab 里）、主进程、IPC 契约、插件系统、外壳布局 |
| **范围外** | 数据存放位置（见 §9）—— 独立决定，不属于本次 |

**关键判断：Vivaldi 的「层系统」是视觉与层级的组织方式，不是载体。** 所以它能 100% 在页面内落地，载体一个字都不用动。

## 8.1 要搬的三条原则（Vivaldi 8.0 "Unified"）

1. **层间无硬分隔** —— 以前 标签 / 工具栏 / 面板 / 内容 之间有细分隔线，现在合成一个连续表面
2. **主题在一层上贯穿** —— 背景从标签栏一路铺到边框不断开
3. **更少的层、更少的例外** —— 层数减少 ⇒ 例外减少 ⇒ 基底更连贯

第 3 条与 NG 主题系统里**已经写死**的原则同源（`shared-types/theme.mjs`：半透明层不许逐层叠加，否则嵌套越深越不透明，"标签条比地址栏深、rail 比面板深"）。

⚠ 但要注意那条纪律的**适用范围**：它针对的是**互相叠放**的层。组件卡片彼此**不重叠**，
各是一块独立的玻璃，不存在叠加 —— 所以"每张卡各自成玻璃"是可以的（并且是保留下来的观感）。
第 1 条同理：它是**外壳**层面的原则（chrome 与内容之间去分隔），搬到"页面内把内容合并成一张板"
会丢掉卡片的分组感与层次感（试过了，被否，见 §8.6）。

## 8.2 真正落地的靶子

| 项目 | 结果 |
| --- | --- |
| 层级靠 CSS 里散落的 z-index，谁在哪层要读代码才知道 | ✅ 显式分层，且只用语义层 token（`--hira-z-*`，门禁 0 违规） |
| 颜色 / 投影 / 蒙层在各选择器里各写一遍 | ✅ 全部集中到 §1 的两处声明（`:root` / `dark`），选择器零字面量 |
| 组件卡片各自成块（散装） | ✅ **保留** —— 曾试图合并成一个连续表面，被否（§8.6） |

## 8.3 目标层结构

```
L0  —         壁纸 / 遮罩   **不在本页**：由窗口外壳唯一绘制（本页透明，见主题系统设计 §6.2.2）
L1  base      内容          .ntp            搜索 + 看板，**各自成块（散装）**
L2  popover   选择器 / 设置  .ntp-pop
```

> 「自定义 / 添加组件」**不再是一条浮在底部的编排条**（`.ntp__toolbar` 已删除）。
> 它们现在是选项卡条**右侧独立的一颗小药丸**（`.ntp__actions`），
> 按钮与选项卡同款 `.ntp-tab` 样式，但**不与选项卡连成一条** —— 详见 §9.3。

层系统体现在 **z-index 语义化 + 分节顺序 = 层序 + 颜色集中在 §1**，
而不是"把内容合并到一张板上"（那条已被回退，见 §8.6）。

## 8.4 六步

> **进度与回退（重要）**
> Phase 0、4 已落地并保留；**Phase 1 – 3 的视觉被回退了** —— 用户实测后明确反馈
> 「不要这样一个大表面层包着，还是以前散装的好」。
> 即：层系统只保留在**内部秩序**上，不落在视觉合并上。详见 §8.6。

**Phase 0 · 定层（只归类，不改视觉）** ✅ 保留

- `newtab.css` 顶部按 §8.3 写成注释分区；分节顺序与层结构一致
- 完成判据：读 CSS 一眼能看出层归属

**Phase 1 · 单一表面** ⛔ 已回退

- 试过：一张大玻璃板（`.ntp__surface`）托住搜索 + 全部组件，组件只作为板上区域、各自不画卡片
- 结果：**观感被否** —— 散装的卡片更好
- 保留下来的是**手段**而非结论：表面原语式的 token 集中、`--ntp-surface-blur` 只在有壁纸时才出现（`blur(0px)` 仍会建 backdrop root，吃掉拖拽跟手度）

**Phase 2 · 网格与表面合一** ⛔ 已回退

- 试过：点阵 → 分区线；拖拽反馈去掉投影
- 回退：恢复点阵与抬起投影（卡片回来了，投影才是正确的"举起"语义）

**Phase 3 · 编排层归位** ⛔ 已回退

- 试过：编排条 / 浮层改用表面原语、去掉各自圆角与阴影
- 回退：各自保留自己的圆角与投影
- 另有一条本来就偏离计划的说明：编排条始终是 `position: fixed`（视口锚定），没搬进内容区 —— 搬进去会压住最后一行组件的右下角

**Phase 4 · 主题贯穿** ✅ 保留

- 页面内已无散落的硬编码色与阴影常量：选择器里不再出现字面量，全部集中在 §1 的
  `:root` / `html[data-theme='dark']` 两处声明一次
- 三类仍然存在的字面量都是**有意的物理件**，各在一处并注明：`--ntp-knob`（开关滑块）、
  `--ntp-scrim` 系列（编辑蒙层的深色渐变 + 白字，压着任意内容故不随主题反转）、
  主题令牌的兜底值与 `var(--hira-warn, …)` 之类 var 兜底
- 唯一保留的"投影"语义已按用途拆成三档：`--ntp-shadow`（卡片）/ `--ntp-shadow-lift`（拖拽）/ `--ntp-shadow-pop`（浮层）

**Phase 5 · 组件契约加「surface 感知」** ⛔ 随 Phase 1 一并回退

- 组件重新各自成卡片；不再要求"组件不画自己的容器"

**Phase 6 · 验收** —— **不做**（用户决定，不再进行应用内的四态视觉验收）

- 当前状态即定稿：**散装卡片**（各自成玻璃，不透明度按原值 74% / 62%）+ 层序清晰 + 零散落硬编码

## 8.5 风险与回滚

- 每个 Phase 独立、可单独回滚 —— 本次实际演练了一次：Phase 1 的大表面整体撤回，只留内部秩序，其余视觉回到原状

## 8.6 回退记录：为什么不做"连续表面"

| | |
| --- | --- |
| **试过什么** | 按 Vivaldi 8.0「Unified」把搜索 + 看板合成一个连续表面：一张玻璃板托住全部内容，组件只在 hover / 自定义模式才出现边界 |
| **为什么试** | 「Unified」的三条原则（层间无硬分隔 / 主题在一层贯穿 / 少层少例外）看起来正对"让新标签页像浏览器 UI" |
| **结果** | 观感被否。"散装"的独立卡片更好 |
| **得到的结论** | Vivaldi 的"连续表面"能搬的是**组织方式**（层级语义化、少例外、主题贯穿），**不能**直接搬成"把内容合并到一张板上" —— 那会同时丢掉卡片提供的分组感与层次感 |

这条记录留着，是为了以后不再重复试同一个方向。

## 9. 分区（首页 / 推广 / 新闻）

仿 Vivaldi 起始页：顶部一排小选项卡，切换三个分区。

### 9.1 分区不是组件

| | 组件（widgets） | 分区（sections） |
| --- | --- | --- |
| 是什么 | 用户能摆的**格子** | **整页** |
| 谁控制 | 用户拖动 / 缩放 / 配置 | 开发者写死 |
| 尺寸 | 网格坐标 | 铺满内容区 |
| 注册 | `defineWidget` | `defineSection` |
| 状态 | `widgets/store.js`（**用户资产**） | `sections/store.js`（使用痕迹） |

两套注册中心 + 两套 store，因为它们回答的是两个不同的问题。**没有一个 if 判断组件和分区的差别** —— 差别体现在类型上。

### 9.2 挂载策略：懒挂载 + 挂载后常驻

- **不在启动时全部挂载**：没点开的分区不该去拉数据（新闻页代价不小）。
- **挂载后不销毁**：切回来时滚动位置、已加载的列表、组件内部状态都还在。

这是"切分区零延迟"的关键 —— 切换只是 `hidden` 的翻转。

> **首帧有个坑，已修**：分区必须在**可见状态下挂载**。看板要在挂载瞬间量真实宽度，
> 若此时分区还是 `display:none`，宽度量到 0 → 按最窄断点排一遍版 → 之后才被
> ResizeObserver 纠正，肉眼能看到错位。所以 `activate()` 的顺序是
> **先让旧分区让位，再挂新分区**，`mountSection()` 刻意不设 `hidden`。

### 9.3 选项卡栏旁的**动作栏**（`ctx.tabbar.addAction`）

选项卡栏右侧还有**独立的一颗小药丸** —— 「自定义 / 完成」「添加组件」就住在那里。

- **不是分区**：点了不切页。
- **不是选项卡栏的一部分**：它是**同级并列**的另一个 `.ntp__actions` 药丸，
  贴在选项卡条右侧、**不与选项卡连成一条**（用户反馈"要单独一个小的"）。
  材质走 §1 那条统一材质，所以看起来与选项卡是**同一族**、但彼此分开。
- **样式**：按钮用与选项卡**完全同一套** `.ntp-tab`；
  编辑中的「完成」直接复用 `.ntp-tab.is-active`，不需要新样式。
- **宿主由切换器自建**：`stripHost.insertAdjacentElement('afterend', actionsHost)` ——
  外壳（index.html）不必知道"选项卡栏旁边还有一颗药丸"，
  分区也不必知道，它们只调 `ctx.tabbar.addAction()`。
- **显隐由归属统一管**：动作项登记时带上 `ownerId`（调它的那个分区），
  `syncActions()` 只让"归属分区正处于激活态"的动作项出现 ——
  于是切到推广 / 新闻时「自定义」自动隐去，**调用方不必自己盯着显隐**
  （那正是"这里一个规则、那里一个变化"的开端）。
- **`selfHidden` 叠加**：「添加组件」只在编辑模式出现，这是调用方自己的条件，
  与"归属分区是否激活"正交 —— 两条与在一起才算显隐。
- 一个可见项都没有时，**整颗药丸一起收起**，不留空气泡占位。

归口在 `sections/switcher.js#addAction`，分区侧只用 `ctx.tabbar.addAction(...)`，
**不认识选项卡栏这个 DOM**，也就不会绕开切换器去操作它。

### 9.4 文档大底（`.ntp-sheet`）

**首页是画布，推广页与新闻页是文档。** 画布上用户摆的格子自己成块、各自成玻璃；
文档整页是文字，没有底座直接压在壁纸上标题就糊 —— 所以大底只给文档型分区。

这不与"不做连续表面"（§8.6）冲突：那次被否掉的是**把首页合并成一张板**，
而这次是"这块内容是画布还是文档"的分类问题。

**有壁纸时大底要明显比卡片更实**（92% vs 卡片 74%）：卡片只是浮在纸上的小块，
一行小字 74% 够；纸上是整页正文与标题，74% 撑不住。所以它不挤进"浮起元素材质"
那条共用规则，而是单独一档 —— 角色不同，不是特例。

一条附带规矩：**大底里的小块不再自己画同色底**（会和纸糊成一片），
改成"透明 + 描边"，层次靠描边与 hover 着色给。

### 9.5 推广页的内容从哪来

**内容全部照抄官网原文**，来源写在 `sections/promotion-content.js` 的文件头（含读取日期）：
`https://www.higheri.tech/` 的主推位、Core Products，以及官网的伙伴赞助区块。

结构刻意很短 —— **头图 → 赞助位 → 其余产品 → 页脚**：

| 位 | 内容 | 为什么在这 |
| --- | --- | --- |
| 头图 | HigheriPE（全新 6.0） | 当期主推 |
| 赞助位 | 伤心的云 | 第三方广告，要显眼 |
| 其余产品 | HigheriDraft / STAR EasyCMD | 同一条线上的另外两个 |
| 页脚 | 官网 / 文档 / GitHub | 想去更深一层时的出口 |

**不放进来的东西，和放进来的一样重要：**

- **STAR Hira**：那是我们自己（这一页就在 Hira 里），自己推自己没有意义。
- **HigheriTab**：它的入口和 Hira 同一个地址，本质是同一件事。
- **路线图 / 品牌理念**：那是官网"关于我们"的内容，不是推广。
  推广页只该回答两件事 —— **现在能用什么** 和 **去哪拿**。
  每多一条，就多稀释一分"这一页在推什么"。

数据与渲染分成两个文件：官网改版后只改 `promotion-content.js`，渲染逻辑一行不动。

两条规矩：

- **站外链接统一代理**：NTP 是内部页，裸 `<a href>` 会把这一页本身导航走。整个分区只挂一个 click 代理全部交给 `ctx.openUrl`；`href` 仍保留 → 中键/右键"在新标签页打开"等原生行为不受影响。
- **伙伴位明确标「广告」**，并且**做得显眼是应该的，但"显眼"不等于模糊掉"这是谁在说话"** ——
  「广告」标签必须留着（那条规矩先于"要显眼"这条需求）。

### 9.6 新闻页复用首页那张卡片的取数

首页的「新闻热点」组件与新闻页**共用** `widgets/news/service.js` + `providers/*`，
所以新闻页里没有一行网络/缓存/降级代码 —— 那三件事只属于 service，换个展示形态不该抄第二遍。

两处各自选源：首页那张卡片的源在组件配置里，新闻页的源在 `sections/store.js` 的偏好袋里
（`getPref/setPref`，不必为每个分区各开一个 localStorage 键）。

### 9.7 页面外壳：右上角时间 + 内部页快捷入口

两样都**不属于任何分区** —— 它们挂在分区容器外面，三个分区上都在。
所以它们既不是组件（不用摆、不能删），也不放在 `sections/` 里（不是一整页）。

快捷入口打开内部页用的是**现成的 `openUrl`**，没有新开通道。这里有一条要记住的事实：

> **`nav:go` 接受 `hira://`。** `TabManager#normalizeUrl` 只做"认识协议就原样保留、
> 不认识就补 `https://`"，而 `hira` 已被 `registerAppSchemes()`
> （`apps/app-main/src/main/scheme-privileges.js`）登记为可浏览协议。
> 所以 `hira://history` / `bookmarks` / `spaces` / `settings` 直接传进去就行，
> **不需要另找 `openPage` 之类的通道（工程里也没有这个东西）**，
> 也不需要新标签页 —— 全工程打开内部页的惯例都是在**当前标签页**打开。

四个入口的 id 都核对过存在（内部页由 `hira-protocol.js` 目录扫描自动注册，
清单在 `apps/app-main/src/pages/README.md`）。

布局上有一处刻意的选择：选项卡与快捷入口**作为一组一起居中**，
而不是"选项卡居中 + 快捷入口绝对定位到右端"。后者在窄窗口下两者会叠在一起。

材质上：两者**共用同一条规则**（`--surface` + 描边 + 投影；有壁纸时统一换成玻璃）。
底槽既然有了底色，**选中态就只加一层着色，不再叠第二层玻璃** ——
同一位置叠两层半透明会把颜色压深，那是这套主题系统一直避免的事。
