# 聚合总览面板（Edge 式「标签操作菜单」）方案

> 目标：一块**聚合入口面板**，一次给出「空间（少量）→ 搜索 → 打开的标签（大量）→ 近期关闭」，
> 每块超限即省略并把去向交给对应的完整面板。Ctrl+Shift+A 落到它并聚焦搜索框。
> 对齐 Edge 左上角「标签操作菜单」的结构，但按 NG 的分层/插件化重做。

---

## 一、结论：选**面板**，不选浮层

用户判断（面板）成立，理由不是偏好，而是四条硬约束：

| 约束 | 面板 | 浮层（独立 WebContentsView） |
| --- | --- | --- |
| **键盘焦点** | 面板已是成熟路径：`mount` 交回 `focusSearch` → 宿主调 `layoutClient.focusPanel` 拿**原生视图焦点**（见 [panels/main.js](../../apps/app-main/src/renderer/panels/main.js) 第 686 行）。 | 需再走一遍 `focusFloat` + 自持焦白名单，且刚落地的那套浮层是「关闭即销毁」，每次打开都重建 renderer（~65ms 起步）。 |
| **实时数据** | 面板常驻订阅（`tab:changed` / `space:changed`），标签一关列表自己就变。 | 浮层开关频繁，长期订阅成本高，且销毁后订阅跟着断。 |
| **「转到 xxx 面板」** | 同一槽位内换面板 = 一次 `panelsClient.toggle`，焦点/滚动/宽度全部延续，用户不跳戏。 | 需「先收浮层、再开面板」两段式，中间必然闪一下，且浮层要不要顺带销毁又是一条特例。 |
| **信息容量** | 面板高度 = 整窗（200~600px 宽可调），「很多标签」摆得下。 | 居中卡片高度受限，与「显示很多大部分标签」直接冲突。 |

因此：**新增一块面板 `overview-panel`**，并把 Ctrl+Shift+A 指向它。

> 与上一步刚落地的 `opentabs-overlay` 浮层的关系：**删除**。它的唯一入口就是 Ctrl+Shift+A，
> 该入口改指本面板后它就是死代码（用户规则：死代码及时清除）。详见第八节。

## 二、与 Edge 菜单的对照

| Edge「标签操作菜单」 | 本面板 | 说明 |
| --- | --- | --- |
| 顶部：垂直标签页开关 / 新建标签 | *不做* | 不在本轮范围（用户只列了三块 + 搜索）。 |
| 空间 / 工作区（少量） | **空间** 块，最多 `2` 个 + `还有 N 个 · 转到空间面板` | 上限刻意压到 2（用户指定）。 |
| 打开的标签（很多） | **打开的标签** 块，最多 `6` 个 + `还有 N 项 · 转到打开的标签页面板` | 复用与「打开的标签面板」同一套行件。 |
| 最近关闭 | **最近关闭** 块，最多 `5` 项 + `还有 N 项 · 转到历史面板` | 复用撤销栈数据（`tab:recently-closed`）。 |
| — | **搜索框**（锚在「空间」与「打开的标签」之间） | 用户指定位置。 |

## 三、布局（唯一一份顺序描述）

```
┌──────────────────────────────────────────┐
│  空间                                     │  ← 块①（最多 2）
│   [ space 1 ]  [ space 2 ]                │
│   还有 3 个 · 转到空间面板                  │  ← 溢出才出现
├──────────────────────────────────────────┤
│  ⌕  搜索打开的标签与最近关闭…               │  ← 搜索框（锚点，常驻不滚动）
├──────────────────────────────────────────┤
│  打开的标签                                │  ← 块②（最多 6）
│   …行…                                     │
│   还有 4 项 · 转到打开的标签页面板           │
│  最近关闭                                  │  ← 块③（最多 5）
│   …行…                                     │
│   还有 2 项 · 转到历史面板                   │
└──────────────────────────────────────────┘
```

- 搜索框**在「空间」块与「打开的标签」块之间**（用户原话）：块①在它**上面**，块②③在它**下面**。
- 「空间」块**不参与搜索**（用户只要求搜「打开的标签 + 最近关闭」），因此输入时它原样留着，
  下面的两块换成**分组结果**。
- 搜索框常驻（`position: sticky`）不随列表滚动，滚动时仍可继续改词。

### 搜索模式

```
│  ⌕  vue                                   │
├──────────────────────────────────────────┤
│  打开的标签 · 3                            │  ← 分组①（命中数）
│   …命中行…                                 │
│  最近关闭 · 2                              │  ← 分组②（命中行）
│   …命中行…                                 │
```

结果**同样分组**（用户原话「标签搜索结果也有这样的分类组」），组标题带命中数；
无命中时该组不出现；两组都没命中 → 一句空态。

## 四、两种模式，一份纯层（解耦要点）

「浏览」与「搜索」不是两套视图，是**同一个纯函数**的两种输出 ——
这正是用户规则里「一个视图要有模式就解耦模块化、统一管理两种模式的特性」的落点。

**新增纯层** `packages/shared-types/src/overview.mjs`（零依赖、零 IO、不 require electron）：

```js
export const OVERVIEW_LIMITS = Object.freeze({ spaces: 2, tabs: 6, recent: 5 })
export const OVERVIEW_TARGETS = Object.freeze({
  spaces: { panel: 'spaces-panel',      label: '空间面板' },
  tabs:   { panel: 'open-tabs-panel',   label: '打开的标签页面板' },
  recent: { panel: 'history-panel',     label: '历史面板' }
})
export const OVERVIEW_MATCH_KEYS = Object.freeze({ spaces: ['name'], tabs: ['title','url'], recent: ['title','url'] })

/**
 * @param {{ spaces:any[], tabs:any[], recent:any[], query?:string }} input
 * @returns {{ mode:'browse'|'search', top:Section[], bottom:Section[] }}
 *   Section = { key, kind, title, items, hiddenCount, overflowText|null, targetPanel, targetLabel }
 *   top    = 搜索框**上方**的块（浏览/搜索都只有 spaces）
 *   bottom = 搜索框**下方**的块（浏览 = tabs,recent；搜索 = 命中后的 tabs,recent）
 */
export function buildOverview(input) { … }
export function searchOverview(input, query) { … }   // 供纯函数复用 / 将来单测
```

渲染层**不认识**「上限是多少、标题叫什么、去向是哪块面板」—— 它只按 `Section[]` 画，
底部再按 `kind` 选一个行渲染器。**加一块新 section = 这里加一条规则 + 一个行渲染器**，
面板本体与宿主零改动。

## 五、数据与 IPC：**零新增通道**

全部复用既有面（已核实）：

| 数据 | 通道 / 客户端 | 出处 |
| --- | --- | --- |
| 打开标签 | `tabsClient.list()`（`tab:list`） | [tabs-client.js](../../apps/app-main/src/renderer/shared/tabs-client.js) |
| 切换标签 | `tabsClient.switchTab(tabId)`（`tab:switch`） | 同上 |
| 最近关闭 | `tabsClient.recentlyClosed()` → `{ tabs:[{url,title,favicon,pinned,index,stackId,closedAt}] }` | 同上 |
| 恢复最近关闭 | `tabsClient.restoreRecentlyClosed(index)`，`index` = **列表下标**（0 最新） | 同上 |
| 当前空间 / 空间列表 | `spaceClient.getUsing()` / `spaceClient.list(profileId)` | [space-client.js](../../apps/app-main/src/renderer/shared/space-client.js) |
| 切空间 | `spaceClient.setUsing(profileId, spaceId)` | 同上 |
| **转到某面板** | `panelsClient.toggle(panelId, {})` | panels/main.js 已注入 `clients.panels` |
| 事件 | `IPC_EVENTS.tabChanged` / `IPC_EVENTS.spaceChanged` | ctx.on |

> ⚠ **恢复下标必须原样保留**：`restoreRecentlyClosed(index)` 认的是**数组下标**，
> 而契约里的 `index` 字段是「关闭前在标签条里的原始位置」，两者不是一回事。
> 因此编排层拉取后统一把每条包成 `{ url, title, favicon, restoreIndex }`（`restoreIndex` = 数组下标），
> 搜索过滤时这个字段**跟着条目走**，绝不重排。

## 六、交互

| 操作 | 行为 |
| --- | --- |
| 点空间 | `spaceClient.setUsing(profileId, id)`（成功后主进程广播 `space:changed` → 重拉） |
| 点「转到空间面板」 | `panelsClient.toggle('spaces-panel')` |
| 点标签行 | `tabsClient.switchTab(tabId)` |
| 标签行右键 | 复用共享的 `createTabRowMenu`（与打开的标签面板**同一份动作表**） |
| 点「转到打开的标签页面板」 | `panelsClient.toggle('open-tabs-panel')` |
| 点最近关闭行 | `tabsClient.restoreRecentlyClosed(restoreIndex)` |
| 点「转到历史面板」 | `panelsClient.toggle('history-panel')` |
| 输入搜索 | **本地过滤**（数据已在内存），不发起 IPC |
| Esc | 收起面板（与其它面板一致：`panelsClient.toggle(panelId)`） |

## 七、模块划分与依赖方向

```
packages/shared-types/src/overview.mjs        ← 纯层：块顺序 / 上限 / 匹配 / 分组（唯一真源）
        ↑ 被下面 import（ui/apps 均不得反向）
apps/app-main/plugins/panel-overview.hira-plugin.json   ← 声明侧（contributes.panels + render）
apps/app-main/plugins/panel-overview.renderer.js        ← 实现侧入口：导出 panelDefinition
apps/app-main/plugins/panel-overview.view.js            ← 画：块装配 + 搜索框锚点 + 三种行渲染
apps/app-main/plugins/panel-overview.rows.js            ← 行渲染器注册表（kind → renderer），加块只动它
```

- 走 **`render` 插件入口**（与 `panel-notes` 同一条路），而**不是**新建 `ui/ui-panel-*` 包：
  仓库当前 `pnpm install` 不可用（缺 `pnpm-lock.yaml`），新建 workspace 包需要手工补
  `node_modules/@hira-ng/*` 链接才构建得起来；`render` 走构建期 glob，**零链接依赖**，
  且更贴合「插件化」主旨。
- `view` 与 `rows` 是**纯渲染**（哑组件）：不持持久状态、不发 IPC，只吃 `Section[]` + 报意图。
  数据拉取、订阅、意图派发全部在 `renderer.js`（编排层），与历史面板同款分工。
- 行渲染器表（`rows.js`）是扩展点：新 kind 只要登记一个 `render(doc, item, ctx)`。

## 八、为什么删浮层、而不是两套并存

两套并存 = 同一个「标签列表」有两个实现，必然漂移（一边加了右键菜单项，另一边没有）。
且浮层的存在理由（Ctrl+Shift+A 要有独立图层）已被「面板 + 原生视图焦点」完全覆盖。
删掉后：**Ctrl+Shift+A → 面板 → 搜索框已聚焦**，一步到位。

---

## 九、扩展点（为后续留的口子）

- **加新块**：`overview.mjs` 加一条 descriptor 规则 + `rows.js` 加一个渲染器。面板本体不动。
- **加新行类型字段**（如标签行的「休眠/静音」徽标）：改对应 kind 的渲染器一处。
- **换上限/换去向**：只改 `OVERVIEW_LIMITS` / `OVERVIEW_TARGETS`。
- **将来要浮层形态**：`view.js` 是纯 DOM，可原样塞进独立浮层渲染页 —— 布局与数据都已在纯层。
