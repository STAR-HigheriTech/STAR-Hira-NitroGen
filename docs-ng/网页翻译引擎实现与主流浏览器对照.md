# 网页翻译引擎实现与主流浏览器对照

## 原实现为什么一直停在“翻译中”

原链路默认请求 `translate.googleapis.com/translate_a/single`。这个地址不需要 API Key，但在部分网络环境会直接超时。页面又按批串行等待，每批内部逐句请求，且只给单次请求设超时，没有页面级总截止时间；网络异常时看起来就会一直翻译。

同时，失败结果被原样当作译文回填，页面用“原文 Map 是否非空”判断成功，导致失败时也可能显示“已翻译”。

## 主流浏览器怎么做

| 浏览器 | 语言检测 | 翻译来源 | 页面处理 |
| --- | --- | --- | --- |
| Chrome | 本地检测组件 + 模型 | 厂商翻译服务，浏览器内部组件鉴权 | 分段、按视口优先、动态 DOM 增量翻译 |
| Edge | 本地检测组件 | Microsoft Translator 的浏览器匿名令牌通道 | 同样按段落与动态内容逐步替换 |
| Firefox | 浏览器内置检测 | Bergamot 本地模型，首次按语言对下载 | 文本节点分段，模型完全在本机推理 |
| Safari | 系统语言能力 | Apple 本地/系统翻译 | 原位替换，依赖操作系统能力 |

共同点不是“调用一个万能免费网页”，而是四层拆开：

1. 语言检测；
2. 页面文本分段与动态 DOM 跟踪；
3. 可替换的翻译提供者；
4. 超时、重试、缓存、失败状态。

## 当前实现

`domain/domain-translate` 是独立领域包，只依赖统一提供者接口：

```ts
interface TranslationProvider {
  id: string
  label: string
  kind: 'plugin' | 'offline' | 'online'
  translate(request): Promise<readonly string[]>
}
```

调度器统一负责：

- 插件 `translate.provider` 永远优先；
- 自动模式依次尝试 Bing 中国直连、Google、Microsoft Edge；
- 相同译文按目标语言与原文缓存；
- 每个来源独立超时，整体默认 8 秒截止；
- 连续失败后熔断 30 秒，避免每页都等待同一个坏来源；
- 返回提供者名称、耗时和逐来源失败原因；
- 插件失败会真正切换到在线来源，不会静默保留原文。

页面 preload 只做 DOM：可见文本采集、视口优先排序、空白保留、原文保存、进度与重试。IPC 只传 `{ texts, from, to }`，不接触任何厂商协议。

Google 适配器使用换行批量协议，一次最多提交 48 个无换行文本；译文行数与输入不一致时自动降级为逐条请求。页面批同时受 `5000` 字符和 `150` 个文本节点双重限制，减少 IPC 往返；来源适配器再按各自协议安全上限内部拆组。

## 免费方案怎么选

### 已接入：Bing 中国直连

`www.bing.com/translator` 在中国大陆可直连。适配器从页面读取短期 `IG / IID / abuse-token`，再调用同一站点的 `ttranslatev3`。不需要开发者 API Key，也不依赖代理；令牌缓存约 55 分钟，失效后自动刷新。

Bing 同样支持换行批量提交。实测无代理环境翻译 48 条短文本约 3 秒，Google 与 Edge 则继续作为其它网络环境下的备用来源。

Bing Web 的单次正文上限实测位于 800–1000 字符之间，因此适配器固定在 900 字符以内，并使用三条串行通道控制突发请求。页面层同一时刻只提交一个页批次，但批次内部仍可并行；DOM 按 24 个节点分片回填，并通过 `scheduler.yield()` 持续让出主线程，滚动和输入不会被长任务卡住。无代理实测 150 条文本约 6 秒完成。

### 已接入：Microsoft Edge 匿名通道

先请求 `edge.microsoft.com/translate/auth` 获取短期 bearer token，再调用 `api-edge.cognitive.microsofttranslator.com`。不需要开发者 API Key，Token 只保存在内存中。

这是 Edge 浏览器自身使用的 Web 通道，并非正式开放 API；协议可能变化，所以必须放在可替换适配器里，并保留 Bing、Google 与插件回退。

### 已保留：Google Web 通道

不收费，但受限网络下可能完全不可达。现在只作为自动模式的第二来源，不再让整页逐句等它。

### 长期免费：Bergamot 本地模型

`@browsermt/bergamot-translator` 已随项目安装。它真正离线，但首次要下载语言对模型，且模型语言覆盖有限。适合作为可选插件或后续离线来源，不应在没有模型时冒充“可用”。

### 需要服务器的方案

LibreTranslate、Argos Translate 自建服务同样免授权费，但仍需一台服务器和带宽。个人桌面浏览器直接内置 Bergamot，成本比长期养服务更低。

## 扩展一个新来源

新增协议适配器后只需注册：

```ts
service.registerProvider({
  id: 'my-engine',
  label: 'My Engine',
  kind: 'online',
  order: 10,
  async translate({ texts, from, to, signal }) {
    return texts.map((text) => translateOne(text, from, to, signal))
  }
})
```

页面、IPC、设置页和失败状态都不需要改动。插件仍可通过 `translate.provider` 覆盖内置来源。

## 用户设置

“设置 → 翻译与语言 → 在线翻译通道”提供：

- 自动切换：Bing 中国直连失败后切 Google、Microsoft；
- Bing 中国直连：只使用无需代理的 Bing Web 通道；
- Microsoft：只使用 Microsoft 通道；
- Google：只使用 Google 通道。

无论选择哪项，已安装的 `translate.provider` 插件仍然优先。
