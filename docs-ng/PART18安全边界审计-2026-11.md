# PART18 安全边界审计（2026-11）

## 信任层级

| 层级 | 代表 | 默认权限 |
| --- | --- | --- |
| 内置外壳 | `file://.../out/renderer/*`、内置 `hira://` 页 | 应用 IPC |
| 第一方插件 | 随包分发、`isFirstParty` | 进程内宿主、完整能力 |
| 社区插件主进程 | `userData/plugins/*` | `utilityProcess` + `ctx.browser` scope |
| 社区插件 UI | `.html` / `.xaml` | opaque iframe + 消息桥 |
| 普通网页 | `http(s)` | 无障碍、自动填充等窄 preload；无应用 IPC |

## 已修复

1. **普通网页可调用全量 IPC**：`tab-preload` 原先向 `http(s)`、扩展页和插件页暴露通用 `window.hira.provider.invoke`。现在 `window.hira` 只注入内置 `hira://` 页；密码填充、下载、手势等 preload 功能仍直接使用 `ipcRenderer`。
2. **社区插件读取原始服务**：隔离宿主原先拿到完整的 `getDomainServices`、`tabManager`、`webContents` 等上下文。现在跨进程上下文只保留 `browser`、生命周期回调和 manifest，所有数据/动作必须经过 `ctx.browser` 的逐方法 scope 检查。
3. **原型链逃逸**：宿主 RPC 现在拒绝 `__proto__`、`prototype`、`constructor` 路径，主进程不再把不可结构化克隆的活对象引用交给社区插件。
4. **插件页/渲染模块提权**：社区插件不能再声明进程内外壳 `render` 模块；可执行 UI 只允许第一方。第三方 UI 统一使用无同源、带 CSP 的声明式面板。
5. **事件越权**：社区插件不能订阅 `*`；共享事件按 scope 放行，主进程事件未知即拒绝，撤销授权或停用会同步摘除监听。
6. **内部页注入逃逸**：页面补丁和 `browser.content.*` 只作用于普通 `http(s)` 页面；用户脚本包也不再接受 `hira:`、`file:`、扩展页等特权匹配。
7. **目录穿越与符号链接**：`hira-plugin://` 与静态页面服务在落盘读取前校验 realpath，链接目标必须仍在插件根目录内。
8. **ZIP/清单资源耗尽**：补上安装包大小、单条目解压上限、总解压上限、ZIP 路径字符与 Windows 设备名、重复路径和清单大小限制。
9. **Node 模块绕过**：`fs` 与 `node:fs` 统一规范化；社区宿主固定使用 CommonJS 加载策略，并启用 Node permission model，只读开放宿主脚本与当前插件目录。工作目录环境被最小化。
10. **IPC 路由回归**：新增集中 audience 策略，默认拒绝。内置 UI 可访问完整契约；普通网页 preload 只能访问密码自动填充、表单填充、正文索引、翻译、手势、文件拖入、GM 请求等显式白名单路由；事件订阅同样按白名单放行。
11. **敏感 origin 伪造**：密码与自动填充请求的 hostname 不再采用页面载荷，由主进程从 `senderFrame.url` 派生；程序化聚焦不能触发地址/支付卡候选。
12. **内部页 XSS 扩散**：所有 `hira://` HTML 统一响应 `default-src 'none'` 基线与严格 `script-src`，同时关闭 object/base/frame 嵌入；原 `profiles` 内联模块已迁为外部模块。
13. **网络 SSRF**：favicon 与插件 `web_fetch` 共用 `infra-net-guard`，拒绝私网/保留/隧道地址，手动处理重定向并逐跳复核。
14. **权限状态分叉**：`clipboard-sanitized-write` 的同步 check 与异步 request 均服从持久化 `block` 决策。
15. **资源协议提权**：`hira://favicon`、`extension-icon` 等资源 host 不再注入应用桥；直接导航 SVG 时统一加 `script-src 'none'` 与 sandbox CSP。
16. **自动填充伪造点击**：密码、地址和银行卡候选只接受可信用户事件；候选内容移入 closed shadow root，页面脚本无法遍历已保存数据摘要。
17. **网页输入伪造**：手势、文件拖入、自动填充聚焦与密码捕获均要求 `isTrusted`；表单提交桥加入交互门槛和一次性令牌。
18. **下载限速死锁**：Electron 下载被节流暂停后会按令牌桶容量自动恢复；MCD 的立即重试改为有界退避，下载不会再永久停住或高频 abort/restart。
19. **持久化写竞态**：`JsonStore` 使用串行写队列，`flush()` 等待真实落盘；后台写入不再产生未处理 Promise rejection 或旧快照覆盖新快照。
20. **重定向与响应体上限**：PWA manifest/icon、插件市场、翻译、每日壁纸、用户脚本、校时与广告列表均改为逐跳公网校验和流式限读；未知 `Content-Length` 不再提前全量读入。
21. **插件动态代码逃逸**：社区宿主锁死 `Function`、`eval`、async/generator 构造器与 `getBuiltinModule` 逃逸路径，加载器单独持有原始编译能力。
22. **站点行为 fail-open**：权限库异常、权限引擎关闭或类型未登记时不再默认放行后台弹窗/下载；仅保留真实用户手势。

## 扩展约束

- 社区插件的可执行主进程入口只能返回可序列化数据、函数或能力门面结果，不能依赖 Electron 活对象。
- 社区 UI 不直接获得 `window.hira`。需要标签、存储、主题等能力时，使用声明式面板的 `window.hira` 消息桥。
- 新共享事件必须同时登记 scope；新增事件不能默认落入社区插件可见集合。
- 新增任意代码注入面时，必须先证明目标页面不是 `hira:`、`file:`、`chrome-extension:` 或插件特权页。
- 新增主进程 IPC 路由必须走 `createTypedIpcMain` 的 sender 授权，不能直接 `ipcMain.handle`。
- 网页 preload 新路由必须同时登记到 `ipc-route-policy` 的显式白名单；不能放宽全局 sender 校验。
- 任何由网页提供的 hostname/origin 都只用于展示；安全判定必须取自主进程 sender。
- 所有网页注入 UI 中的可执行动作必须检查 `isTrusted`，含敏感内容的浮层优先使用 closed shadow root。
- 所有可跟随重定向的主进程网络请求必须逐跳校验目标，并以流式方式执行响应体上限。
- `buildWebPreferences()` 的安全字段不可由调用方覆盖；确实需要特权原语时应新增窄端口，而不是关闭 sandbox/contextIsolation。
- 新增 `ctx.browser` 方法必须在该方法内部做 scope 判定，注册中心不复制业务权限规则。

## 尚存边界

Electron `utilityProcess` 提供崩溃隔离，不等同于 Chromium 渲染器级安全沙箱。当前 Node permission model 主要限制文件系统、子进程、Worker、WASM 和原生插件；它还没有逐插件的网络白名单。宿主已删除 UI 级插件的全局网络对象、拦截 `process.binding` 与动态 `import()`，但这不是最终安全证明。后续若加载不可信远程插件，应把主进程代码迁入无 Node 集成的专用 sandbox renderer，并由宿主 broker 提供文件与网络端口。
